From internal writes to token coefficients and probability changes

Two new lenses on the same saved adapters: how strongly each token activates a rank-1 branch, and how much that adapter changes the distribution of the next token.

Status: explanation of the approved ticket, not an implementation or scientific result. Its first task is to freeze coefficient conventions, prediction-position masks, reductions and memory limits. Examples below illustrate the mathematics; they do not select those settings.

We apply the supplemental product to both existing SFT and GRPO checkpoint trajectories. There is no SFT retraining or repeated answer generation. Ticket 7's random intervention remains a separate control; Ticket 8's stated scope requires these new measurements for the two trained arms.

Why both quantities? A large internal change can have a small effect on output probabilities. A mean write can also conceal opposing token effects. Coefficients preserve token variation; KL reads distributional change at the model output. Neither alone establishes damage or a causal mechanism.

2. Rank 1 turns a vector input into a scalar and back

At one adapted linear projection, the token supplies a vector x. The frozen projection computes W x. LoRA adds a branch with input factor a, output factor b and scale s = alpha/r.

Module input xOne hidden vector for one token, at this module.
→
Input factor aᵀc = aᵀx
One signed scalar.
→
Output factor bb × c
A vector in output space.
→
Scale and addu = s b c
Output = W x + u
A has shape [1, input dimension]; B has shape [output dimension, 1]
c = A x = aᵀx
adapter contribution u = (alpha/r) B c
For this protocol: r = 1, alpha = 1, dropout = 0 → s = 1

Example: x = [2, −1], a = [0.5, 1] gives c = 0. The branch is zero for this token even if both learned factors are nonzero. If x = [4, −1], c = 1; with b = [3, −2] and s = 1, the branch adds [3, −2]. A negative c reverses that output direction.

This coefficient is associated with a module input during a particular adapter pass. Earlier adapted layers can change x. Same text does not imply the same hidden vector. The convention must explicitly state which pass supplies x; reconstructing the actual adapted branch uses its actual adapted-pass input.

There are 28 layers × 7 projections = 196 adapted modules. We keep coefficients per token per intended module, with example ID, token position, view/mask, checkpoint, factor hashes, scaling and numerical provenance. They are not attention weights or rewards.

3. A raw coefficient has no universal scale

Replace a with k·a and b with b/k, for nonzero k:
c becomes k·c, but s·(b/k)·(k·c) = s·b·c
The model's branch is unchanged.

The same effective weight update can therefore have different coefficient values. Even its sign can flip when both factors flip. Save the factors/scaling identities and interpret c alongside b. Across checkpoints, a larger raw coefficient is not automatically a larger functional effect.

Factor-dependent readingRaw c tells us the input projection in this saved factorization. Useful for reconstruction and token-level inspection.
Function-related reading||s b c|| describes branch magnitude on that input. It also depends on the context, but is invariant to reciprocal factor rescaling.

Coefficient normalization, sign conventions and stored scaling belong in the new config. We should not silently normalize the saved trained factors or overwrite an adapter.

4. KL compares every possible next token

For the identical prefix, let p be the tuned model's next-token probabilities and q the untuned model's. Ticket 8 specifies the direction KL(tuned || untuned).

Same prefixFixed saved text up to a prediction position.
→
Two forward passesTuned logits and untuned logits over the full vocabulary.
→
Normalizelog-softmax gives log probabilities; p weights the difference.
→
Reduce vocabularyΣ p(v) [log p(v) − log q(v)] → one scalar.
KL(p || q) = Σ over vocabulary v: p(v) log[p(v)/q(v)]
Natural logarithms → units are nats. This is not an accuracy percentage.

A two-token illustration: tuned p = [0.8, 0.2], untuned q = [0.5, 0.5]. The KL is approximately 0.193 nats. Reverse the direction and it is approximately 0.223 nats. Identical distributions give zero. The real product includes the full model vocabulary, not only the gold token or A/B/C/D.

KL is not “wrongness”. Moving probability toward a correct answer can produce positive KL. Moving it toward an incorrect answer can also produce positive KL. Read it with behavioural scores and internal writes. No universal “harmful KL” threshold is authorized.

We use stable log-probability calculations and record accumulation precision. Floating-point rounding can produce tiny residuals near zero; their handling needs independently justified numerical checks, not an undocumented clamp.

5. The off-by-one issue: a token and its prediction are different positions

Position 0: “The”Hidden state/logits here predict position 1.
→
Position 1: “answer”Logits here predict position 2.
→
Position 2: “is”Logits here predict position 3.
→
Position 3: “3”Its coefficient describes processing “3”; predicting “3” used position 2.

The scalar coefficient at position t describes processing the supplied token t. Logits at t describe the next-token distribution after the prefix through t. If a KL view means “predictions of solution tokens”, the mask for target token t+1 must be mapped back to logits position t.

The first solution token may be predicted from the final prompt-format position. That boundary can count under a target-token view even though the context position itself is not solution content. Alternatively, a context-token view would define membership differently. These are distinct questions and must be frozen before collecting data.

Padding never counts. Handling the first token, final supplied token, chat markers and end-of-turn targets must be explicit. Tiny identifiable sequences should independently test these boundaries rather than copy the implementation's own mask logic.

7. Memory: keep the useful scalars, not all logits

A coefficient requires one scalar per module/token. Full-vocabulary logits require a scalar for every vocabulary entry at every context, in two model passes. That is a very different memory budget.

Illustration only: batch 8 × 512 positions × vocabulary 150,000 × 4 bytes
≈ 2.29 GiB for one FP32 logit tensor; two such tensors ≈ 4.58 GiB
before activations, model weights and log-probability temporaries.

196 coefficients × 512 tokens × 4 bytes ≈ 0.38 MiB per example.

We need bounded chunks: compute paired distributions for a limited set of positions, reduce across the vocabulary, persist the resulting KL values, and release large temporaries. Calling a full model forward that already allocates all logits and chunking afterward does not prevent the original peak allocation. Chunking must act at the point where large tensors would be created.

Vocabulary chunks require correct global log-softmax normalization; each vocabulary chunk cannot be normalized independently. Whether to chunk positions, vocabulary, or both is an implementation choice to verify against a small independent calculation.

The frozen gold sequences remain intact. Chunking the output head is not permission to break causal context or shorten a gold solution. Recomputing decoder passes to save memory can cost more time; profiling should expose that tradeoff.

No reliable time estimate yet. Ticket 7's internal-body throughput excludes this vocabulary work. We must measure loading, decoder/head execution, hooks, transfers, hashing and disk writes at passing batch/chunk settings. Memory limits and a reviewable workload estimate precede a full run.

9. What remains to be decided before building?

  • Coefficient convention: raw versus scale-inclusive values, explicit input pass, sign/factor provenance, and any additional normalized reading.
  • KL position convention: context-view versus next-target-view membership and all sequence boundaries.
  • Reductions: exact per-token records, per-example summaries and whether both existing token-weighted/equal-example summaries apply to KL. These weights can change the aggregate when lengths differ.
  • Resource settings: chunk dimensions, memory budget, retention/storage dtype, accumulation precision and frozen batching.
  • Validation binding: supplemental numerical evidence, accepted comparison scales and whether any existing calibration can legitimately be reused.

The approved ticket explicitly requires these to be frozen. We will explain options and recommendations before selecting scientific conventions. This page does not silently fill those gaps.

10. What would the result let us say?

We could report that one arm changes next-token distributions more on supplied GSM8K contexts than FineWeb contexts, or that its rank-1 branches engage unevenly across tokens/modules. We could inspect whether a small mean write hides large opposing per-token effects.

We could also retain KL trajectories for later comparisons at similar distributional change. Equal steps, equal weight norm and equal KL do not imply equal training progress or identical mechanisms. A fixed-context KL average is not the distance between unconditional generated-text policies: the contexts are supplied by our measurement corpus, not sampled from every model's own trajectories.

Coefficient: token-level branch engagement in a saved factorization
Write: change in internal activations on supplied text
KL: change in next-token probabilities on supplied prefixes
Accuracy/length: behaviour under a specified generation policy
Read these together; keep causal claims for separately controlled interventions.
