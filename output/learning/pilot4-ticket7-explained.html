Ticket 7: where and how does GRPO write?

Follow the same tokens through the untuned model and its adapters. Separate local branches from accumulated block changes, then compare magnitudes and directions.

1. What question is Ticket 7 answering?

Ticket 5 produces trained adapters. Ticket 6 asks what happens to their answers. Ticket 7 asks: on the same supplied text, how do those adapters change internal computations, at which layers, and in which directions?

An activation is the vector of numbers produced inside the model while it processes a token. A write is our operational name for a measured change caused by enabling an adapter. It is an observation at a particular hook and context—not a claim that the model stored a discrete piece of knowledge there.

Ticket 5 · trainSealed GRPO adapters at steps 0, 8, 16, 32, 64
→
Ticket 6 · behaviourGenerated answers, accuracy and response length
→
Ticket 7 · internal measurementFixed-token block writes, module contributions and directions

Tickets 6 and 7 both depend on verified Ticket 5 checkpoints. Ticket 7 does not need Ticket 6’s generated answers as input, so the two products can run in separate GPU sessions. Pilot 3 supplies the fixed sequences and established measuring instrument.

Status: This is a design guide for the approved Ticket 7. Ticket 7 is not implemented yet. Existing Pilot 3 functions are real; the GRPO source integration and random-control workflow remain to be built.

2. First fix the text, then change the model

If an SFT model writes a short answer and a GRPO model writes a long answer, their internal states are processing different words. Comparing those states mixes the adapter effect with the changed input. Ticket 7 supplies the same saved token sequence to every model variant.

Saved GSM8K sequenceQuestion + complete gold solution
→
Untuned forward passBaseline activations at every decoder-block output
→
Adapted forward passSame tokens and positions; one adapter enabled

This is sometimes called teacher forcing: the gold answer tokens are supplied as context rather than generated. A causal language model processes each position using preceding text; the forward pass can compute many positions together. There is no answer-generation loop here.

Reuse the exact 150 GSM8K and 150 FineWeb sequences, token IDs, masks, position rules, order and hashes. Padding, chat-format tokens and excluded positions do not silently enter the content averages. We do not redownload a new FineWeb sample or truncate gold solutions to make this run faster.

Limit: this answers how the model processes fixed gold reasoning. It does not directly measure the internal states of the reasoning it would generate itself. Length changes remain a separate behavioural observation.

3. A block contains several adapted modules

A decoder block is one transformer layer. An adapted module is one linear projection inside that layer. Qwen’s 28 blocks each have seven targeted projections: 196 LoRA modules altogether.

Residual input hThe current token representation
→
Attentionq / k / v projections → attention mixing → o projection → residual addition
→
MLPgate and up projections → gated product → down projection → residual addition

Block outputRepresentation sent to the next layer

The diagram is schematic: Qwen also applies normalization within the block. o_proj maps attention’s mixed representation back into residual-stream coordinates. down_proj maps the expanded MLP representation back into those coordinates. Both write into the residual path, but the earlier projections can change what they receive.

The block-output hook reads the accumulated output after these operations. The module hooks read an individual ordinary projection and its own LoRA branch. These hooks observe different quantities, so their curves need not agree.

4. What does a rank-1 adapter do?

An ordinary linear projection maps an input vector x to W x. Rank-1 LoRA adds one outer-product update. Its input factor a reads one scalar from x; its output factor b writes that scalar along one output direction.

ΔW = s · b aᵀ, where s = α/r = 1 for this recipe
ordinary output = W x
direct adapter contribution = ΔW x = s · b (aᵀx)
adapted module output = W x + s · b (aᵀx)
x · current module inputTaken from this adapted forward pass
→
Read coefficient aᵀxOne signed scalar per token
→
Write along bScale b by s and the coefficient
→
Add to ordinary outputW x + direct contribution

Direct means the module’s own branch on the same current input. The input x may already have changed because of earlier adapters. Therefore direct contribution is not the entire difference between this module’s output in two separately run networks.

If x′ is the adapted input:
(W + ΔW)x′ − Wx = W(x′ − x) + ΔWx′
propagated input change + own direct contribution

This decomposition is exact for the ordinary linear map. Later nonlinear operations and attention interactions make the full block change more complicated. We cannot sum 196 scalar ratios to recover a whole-network effect.

5. The two primary measurements

A. Total block-output write

For each counted token, subtract the untuned block output from the adapted output. This includes the local adapters and effects propagated from earlier blocks.

δhₗ,t = hₗ,t(adapted) − hₗ,t(untuned)
mean write vector μδ = weighted mean of δh
primary block relative write = ||μδ||₂ / weighted mean of ||h(untuned)||₂

B. Direct module contribution

For each counted token, compare the module’s own LoRA branch magnitude with its ordinary projection magnitude on that same adapted input.

dₗ,m,t = s · b(aᵀx)
oₗ,m,t = W x
primary module ratio = weighted mean of ||d||₂ / weighted mean of ||o||₂
QuantityNumeratorWhat it emphasizes
Block relative writeNorm of the mean change vector.A coherent average direction across the counted tokens.
Module ratioMean direct-contribution magnitude.How large the branch’s local intervention is, regardless of sign cancellation.

These are activation measurements, not relative weight differences. A high module ratio can come from a large branch, a small ordinary denominator, or both. Save both magnitudes and coverage so the ratio remains interpretable.

6. Why save several magnitudes and the actual vector?

A vector can cancel when averaged. Two token changes, (1,0) and (−1,0), each have magnitude 1. Their mean change is (0,0), whose magnitude is zero.

Mean of magnitudes = 1Individual tokens moved substantially.
Magnitude of mean = 0There is no common average direction in this toy case.

Ticket 7 preserves both. It also saves the mean baseline vector and its magnitude as a denominator diagnostic. The primary denominator is mean baseline magnitude, which avoids cancellation in the baseline average. The alternative ratio using the magnitude of the mean baseline is diagnostic, not a silent replacement.

The saved mean write vector is needed for direction comparisons and possible later steering. A scalar magnitude loses which way the change points. A mean vector that is zero or below calibrated resolution does not support a reliable direction claim; report it as unresolved with coverage.

For modules, also retain the conditional average of per-token ratios. That diagnostic averages ||d||/||o|| only where the token denominator is nonzero. It differs from the primary ratio of averaged magnitudes. Zero denominators are recorded rather than hidden by an arbitrary epsilon.

7. Whose tokens get how much weight?

Long gold solutions supply more activations. Token weighting gives every token equal influence, so longer examples matter more. Equal-example weighting first averages each example’s counted tokens, then gives each nonempty example equal influence.

Token-weighted mean = sum over all counted tokens / total counted tokens
Equal-example mean = average of each example’s within-example mean
Toy exampleToken countMean change on one coordinate
Short solution101
Long solution903

Token weighting gives (10×1 + 90×3)/100 = 2.8. Equal-example weighting gives (1+3)/2 = 2.0. Neither is universally correct: they answer different averaging questions. Report both under the same definitions and masks.

Keep the earlier pinned question visible: do long gold solutions dominate the token-weighted profile? This concerns fixed gold lengths. It does not explain why an adapter generates shorter answers.

Use one loaded model. For each frozen input batch, compute an untuned reference, then switch adapters and compute the matched adapted passes sequentially. Examples inside the batch run together. Full reference token activations can be held temporarily for that batch and released after reductions.

Baseline-cache reuse needs the disabled-adapter invariance check: turning off each loaded adapter must reproduce the same untuned reference within the declared instrument contract. The cache cannot be trusted solely because two files name the same model.

A valid GRPO source is its own verified contract. The existing activation preparation checks an SFT source specifically; Ticket 7 must add GRPO support explicitly rather than giving GRPO artifacts an SFT-shaped filename or bypassing checks.

9. Three different kinds of evidence

EvidenceQuestion it answersWhat it cannot establish
Instrument identitiesAre hooks, masks, zero writes, rank-1 algebra and frozen weights correct?Whether GRPO improved or harmed behaviour.
Numerical calibrationHow much discrepancy do equivalent permitted computations produce?A scientific null distribution for learned directions.
Random adapter referenceWhat does one matched random intervention write on these contexts?A numerical error bound or a population significance threshold.

Earlier, arbitrary tight elementwise tolerances rejected correct floating-point computations across batch shapes. Later, repeated full weight hashes dominated runtime. The lessons are to calibrate numerical agreement on meaningful scales, profile the complete path, and place full hashes at integrity boundaries.

Calibration and validation remain distinct: calibration estimates an engineering envelope; separate validation checks that it accepts equivalent computations and rejects intentionally wrong mappings, signs or scaling. A 3× engineering margin is not a 95% confidence guarantee.

Reuse old calibration only when the verified identity contract permits it. FP32 by itself is insufficient: model, runtime, settings and batch/context identities matter. Changed precision/runtime requires new evidence. Do not loosen a failed gate to obtain a faster batch.

10. Why one norm-matched random rank-1 adapter?

A trained write can align with a comparison vector partly because the model responds anisotropically—some directions are naturally amplified. One random intervention offers a concrete reference under the same contexts. It is not a complete estimate of chance alignment.

The displayed balanced factorization is an implementation option, not a new approved scientific parameter. The contract fixes independent unit directions and the effective update norm, including LoRA scaling. Save the chosen construction, realized factors and hashes before measurement.

Weight-norm matching does not match activation-write magnitudes. The coefficient aᵀx depends on which directions the contexts occupy, and downstream propagation is nonlinear. Measure the realized activation magnitudes instead of assuming they equal the trained adapter’s.

The control uses an isolated RNG so it cannot advance the training or other experimental random streams. It creates a new adapter product and never edits either source arm. One random realization cannot provide a 95th-percentile null or justify a universal 0.05 cosine threshold.

11. How to read the direction comparisons

Signed cosine(u,v) = (u·v) / (||u||₂ ||v||₂)
+1: same average direction · 0: orthogonal · −1: opposite

At a given layer, compare corresponding mean block-write vectors under the same view and weighting. Ticket 7 requires the random control’s per-layer signed cosines against compatible SFT and GRPO mean writes. Preserve identities and resolution flags when reusing SFT vectors.

For example, GRPO and SFT could have similar write magnitudes but opposite directions. Or they could have small cosine while sharing a behavioural effect. The averages can also conceal several distinct token-specific directions.

A negative cosine is not proof that GRPO heals SFT by subtraction. These arms were trained separately from their starting model; cosine describes a geometric relationship on supplied contexts. A causal claim needs an intervention that changes behaviour while controlling the relevant alternatives.

Zero denominators make cosine undefined. Directions below measured resolution remain flagged; do not turn them into a confidently interpreted zero alignment. Small mean directions can coexist with large individual token changes.

13. Where does GPU time go?

A forward pass processes all supplied positions together, so it avoids the repeated next-token generation loop. It still has real cost: long contexts, attention, 196 instrumented modules, per-token reductions, temporary reference storage, validation passes, transfers and persistence.

For illustration, 300 sequences at batch 8 require 38 batches. One reference plus five GRPO adapters plus one random adapter means roughly 38 × 7 = 266 main forward passes, excluding validation, warmup and integrity overhead. This is a workload count, not a runtime estimate; the actual passing batch and scheduling remain to be implemented/profiled.

Within each batch, examples run together. The adapter passes run sequentially on one GPU. Padding to the longest sequence means batch composition matters. Generation tokens/sec from Ticket 6 does not predict this instrument’s forward-and-reduction throughput.

Progress must show the current phase, batch and adapter, not just a repeatedly printed unchanged counter. Wait for the actual child exit and verify durable completion. A defunct process is not a still-running experiment; partial sealed shards are recovery evidence, not a final report.

15. What would an interesting result mean?

If late-layer o_proj or down_proj ratios are high, their own adapter branches are large relative to ordinary outputs on those contexts. Look at numerator, denominator, earlier modules and block writes before claiming a special role.

If block writes are large on GSM8K solution tokens but small on FineWeb, that suggests context-dependent effects under these measurements. If both are large, it suggests broader internal drift. Neither observation alone establishes retained or lost capability.

Follow-up causal experiments could selectively disable a module/layer adapter, patch matched block states, or steer along a resolved mean direction and evaluate behaviour with controls. Ticket 7 helps choose and quantify such interventions; it does not perform them or show that a mean direction is sufficient.

Internal change ≠ behavioural damage
Direct branch ratio ≠ causal importance
Mean-write alignment ≠ the same mechanism
One random reference ≠ a null distribution
Verified measurement → interpretable evidence → separately designed causal test
