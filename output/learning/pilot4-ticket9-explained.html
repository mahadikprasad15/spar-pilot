Bring the evidence together—and make it runnable

The final ticket builds a verified SFT–GRPO comparison and completes the Colab handoff. It turns separate saved measurements into a report that tells you what changed, on which inputs, and what the comparison can support.

Status: Ticket 8 implementation and offline CPU tests are complete. Actual source/GPU validation and measurements remain separate Colab work. Ticket 9 is not implemented yet. All numerical examples below are illustrative, not research results.

3. What the plots mean

PlotAxes / seriesFormula, population and limits
Behaviour trajectoryStep → accuracy or generated length; SFT and GRPO.Greedy: same 150 held-out items. GRPO sampled endpoints: mean correctness over eight draws per item, then items; not pass@8. Paired item-bootstrap intervals condition on one training seed. Missing SFT sampled results stay unavailable.
Write depthLayer → relative mean write; checkpoint lines; separate views/arms/weightings.‖mean(h adapted − h base)‖ / mean‖h base‖. Supplied GSM8K question/solution or FineWeb tokens, not independently generated answers. Cancellation can make the mean small.
Direct module contributionLayer → contribution ratio; projection facets.Local LoRA branch relative to untuned linear output, using the existing frozen reduction. This differs from a block-output change that includes propagated effects.
Signed direction comparisonLayer → cosine of SFT and GRPO mean-write vectors.Matched view, weighting and compatible precision. Unresolved or zero directions are flagged; no manufactured angle.
KL trajectoryStep → fixed-context KL; arm/view/weighting series.KL(tuned || untuned) over the full next-token vocabulary; context positions assigned to next-target view. This is not unconditional generated-policy distance.

Every plot must state its denominator, counted population, uncertainty source and missing-data coverage. Existing activation uncertainty/calibration policies remain in force; this ticket does not invent a new empirical noise threshold.

Token weighting versus equal-example weighting

If one example has 2 measured tokens with average KL 0.1 and another has 8 tokens with average KL 0.5, token weighting gives (2×0.1 + 8×0.5)/10 = 0.42. Equal-example weighting gives (0.1 + 0.5)/2 = 0.30. The first emphasizes tokens; the second gives each example equal influence. Both are reported with coverage.

4. A concrete direction example

SFT mean write u = (3, 4)Magnitude 5. These are illustrative two-dimensional vectors.
GRPO mean write v = (4, −3)Magnitude 5; u·v = 12−12 = 0.
cos(u,v) = (u·v)/(‖u‖‖v‖) = 0/25 = 0

These writes have equal magnitude and perpendicular directions. That alone tells us neither which model is more accurate nor whether one write causes harm. A negative cosine means opposing mean directions at this measured site; it does not prove that GRPO heals SFT. If either direction is unresolved, the report must mark the cosine unavailable.

5. Equal steps is only one comparison

Equal optimizer stepsSame update count; different signals, completions and gradient sizes can produce different changes.
Equal write magnitudeSimilar internal-change scale on a specified corpus; directions and outputs can still differ.
Equal KLSimilar distributional change on fixed contexts; accuracy and internal geometry may differ.
Matching ledgerPrecision, data source, completion count, loss, scorer and input differences remain visible.

SFT learns gold solutions; GRPO learns from its own sampled completions and rewards. Shared problems and adapter size do not make this an objective-only causal comparison. An early SFT checkpoint is a descriptive preview, not a substitute for a lower-learning-rate SFT run. Historical 64%→42% and 288→77 values remain context, not pass/fail criteria.

→
Random rank-1 factorsIndependent unit directions, isolated seed 42; match each effective norm including α/r.
→
Same fixed-input instrumentMeasure realized activation magnitudes and signed cosines.
→
Reference in reportCompare learned writes with this one realization.
‖ΔW‖F = |α/r| × ‖B‖ × ‖A‖

Equal weight-update norm does not guarantee equal activation change: the input distribution matters. One random adapter cannot estimate a null percentile or p-value. A theoretical isotropic cosine value such as 0.05 is not an empirical model-write noise floor. Numerical instrument calibration is a separate check.

CPU tests need no model downloads. They check software and artifact contracts. Target-GPU execution validates the actual scientific workflow separately. Tests will use red/green TDD and retain prior acceptance thresholds.

9. What completion will mean

  • A CPU-only report builder consumes verified source evidence and exposes compatibility, missingness and limitations.
  • Behaviour, depth profiles, signed cosines and KL trajectories are readable together, with formulas and worked examples.
  • The guided notebook has explicit completion, recovery, GPU-release and artifact-download steps.
  • Controlled workflow and notebook tests pass; implementation is committed.

Software completion does not mean the GRPO experiment has run, or that it found an accuracy gain, a collapse or a causal mechanism. Null and inconclusive results can still be valid scientific outcomes.
