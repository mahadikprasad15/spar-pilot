01 / The scientific question

What does fine-tuning change?

The wider project studies how much, where, and in which direction a fine-tune writes into a model. These pilots establish behavioral measurements and produce an adapter for later analysis.

PILOT 1

Build the ruler

Measure untuned arithmetic, multiple-choice knowledge, response length, and sensitivity to scoring.
→
PILOT 2

Apply an intervention

Train a rank-1 LoRA on 512 gold GSM8K solutions for 64 optimizer updates.
→
MATCHED COMPARISON

Use the same ruler

Compare untuned and adapted responses on identical held-out items, prompts, precision and scorers.
The earlier team reported 64% → 42% accuracy and 288 → 77 response tokens. We lack its full recipe and item list. Our work is a new versioned protocol; historical gaps are descriptive. A shorter response or lower accuracy alone does not identify where the adapter wrote or establish a mechanism.

03 / Before the model sees anything

Examples live inside the user message

Where do the 1,140 items come from?

57 MMLU subjects
×
20 test items per subject

A seed-42 random sample is drawn separately for each subject, in sorted subject order. Indices and content are saved. Equal subject counts give each subject equal weight in aggregate accuracy; the full test set has different subject weights.

GSM8K uses 150 sampled official test items, also seed 42. Pilot 2’s 512 training items come from the separate official train split.

What does “5-shot” mean?

For each MMLU test question, prepend the first five dev questions from that same subject, with their correct answers. Dev is a separate demonstration split.

USER MESSAGE
  instruction: choose A / B / C / D
  dev[0]: question + choices + correct answer
  dev[1] ... dev[4]: same format
  test item: question + choices (no gold)

ASSISTANT PREFIX
  Answer:

All test questions in a subject reuse its five demonstrations. These are context, not optimizer training. At 0-shot, the demonstrations disappear.

The rendered Pilot 1 prompts include Qwen’s default system message. The original written protocol specified no system message. This discrepancy is recorded; Pilot 2 preserves the actual rendered prompt for a matched comparison.

Tokenizer → model → tokens → text

The tokenizer renders chat roles and special tokens, then converts text to token IDs. The model predicts a score for every vocabulary token at the next position. Decoding converts the chosen token IDs back to text.

prompt text → token IDs → model forward
                         ↓ vocabulary logits
                   choose next token
                         ↓ append to context
                   repeat until EOS or cap
                         ↓ decode new tokens only

Token length is not word count. We count generated tokens before EOS, excluding padding.

Greedy versus sampled decoding

Our evaluations are greedy: at every step choose the highest-scoring vocabulary token. No random sampling or temperature sampling is active.

Sampling, for later pilots: choose randomly from a probability distribution. Temperature rescales logits before softmax; higher temperature generally spreads probability, lower temperature concentrates it. Sampling can reveal reasoning variability, but changes the measurement protocol and needs saved seeds/settings.

MMLU constrained scoring restricts the comparison to A/B/C/D token logits. It can choose a letter even if another vocabulary token would win unrestricted greedy generation. Softmax is unnecessary for argmax because it preserves ranking.

04 / The measurement instrument

A scorer measures an answer through a rule

Keep three questions separate: did it follow the format? can we extract one answer? does that answer match the gold value? The model can reason correctly while failing an extraction rule.

GSM8K strict

Requires a final line shaped like #### 3, plus consistency checks. Parse an exact numeric value and compare to gold.

Good for format compliance. It can undercount correct prose answers.

Flexible v1 → v2

V1 recognized a narrow set of final-line phrases and bare numbers. V2 uses regex cues and numeric grammar over a conclusion region; surrounding prose and units are allowed.

V2 is broader, but conservatively rejects multiple distinct numbers. It does not understand language semantically.

MMLU

Text: accept a leading answer letter under the parser’s allowed form; competing later A/B/C/D mentions or capped output invalidate it.

Logits v2: choose the unique largest candidate score. Equal maxima are invalid and incorrect, then continue the run.

Why not grab the last number, or ask another LLM to grade?

The last number may be a context quantity or an unfinished calculation. An LLM judge introduces its own model, prompt, variability and potential biases. Our deterministic grammar is auditable and CPU-only, but has explicit limits: spelled-out numbers, scientific notation and LaTeX fractions are outside v2’s initial grammar. “36 hours in 4 weeks” remains ambiguous.

Offline v2 rescoring preserves raw generations and old scores, writes a new report with hashes, and labels Pilot 1’s revised measurement post hoc. V2 is frozen before Pilot 2 so a training result cannot silently change the ruler.

05 / Pilot 2 mechanics

Train the adapter, keep the base frozen

Rank 1 is a small trainable detour

A maps the input vector into one scalar; B maps that scalar back to an output vector. Here r = 1 and α = 1, so the scale is 1. A starts random, B starts zero; the initial adapter adds zero.

The adapter is attached to q, k, v, o, gate, up and down projections in each of 28 layers: 196 modules. The language-model head and embeddings remain frozen. Hashes check that base weights do not change.

Gold solutions supply the targets

systemuser problemassistant startgold reasoning#### answerend-turnpadding

Green / purple: supervised target tokens.
Gray: labels = −100, ignored by the loss.

The model still reads the prompt. It is penalized only for incorrect next-token predictions in the assistant completion, including its end-turn token. Labels shift by one position to train next-token prediction.

Original calculator annotations and #### markers are retained. No packing joins examples; no truncation cuts solutions. Maximum length comes from the longest fully rendered training example.

Eight microbatches make one optimizer update

REPEAT 8 TIMESOne problem → forward → completion loss → backward → accumulate adapter gradients.
→
ONCEClip gradients → AdamW update → clear gradients. Frozen weights receive no optimizer update.
→
REPEAT 64 UPDATES8 × 64 = 512 example exposures, one frozen shuffled pass through the selected data.

Training microbatch 1 limits memory. Effective batch 8 describes the update’s data. Yesterday’s evaluation batch 8 grouped independent inference items; it did not train anything.

The custom loss sums cross-entropy over supervised tokens and normalizes across the full accumulation window. This avoids giving short and long microbatches equal weight simply because each contains one example.

The libraries provide model loading, tensors, adapters and trainer machinery. Our code owns sampling, prompt identity, completion masks, exact loss normalization, extraction rules, artifact verification and matched comparisons. Library defaults cannot silently substitute for these scientific choices.

Why were specs, tickets and tests needed?

Spec: fixes what the experiment must do. Tickets: break that contract into implementation steps. Tests: check observable behavior at those boundaries. A test that initially fails because a feature does not exist is the “red” phase of test-first development; it is not evidence that the scientific hypothesis failed.

Pure CPU tests

Fake model/dataset boundaries check sample IDs, scoring edge cases, config locks, recovery, saved artifacts and paired comparisons without downloading weights.

Real tiny CPU model

A Qwen architecture built locally from config exercises real TRL/PEFT masking, accumulation, frozen weights and checkpoint resume. It tests library integration, not Qwen 1.5B capability.

Real GPU preflight

Qwen on the T4 checks the longest sequence, finite loss/gradients and optimizer allocation. A disposable update restores the adapter; scientific training starts afterward.

Current session: 111 tests passed, with five PEFT warnings about the locally constructed tiny model lacking a downloaded config file. Passing CPU tests does not prove the full model will fit GPU memory or reproduce a collapse.

What Pilot 2 will report

ACCURACY CHANGEPair each adapted prediction with the baseline prediction for that same question. Bootstrap item pairs, preserving their relationship.
+
LENGTH CHANGEMean adapted length − mean baseline length; also mean adapted length / mean baseline length.
+
UNCERTAINTYWilson intervals for scores; 2,000 paired bootstrap draws for changes. One training seed: no estimate of between-seed variability.

No binary collapse threshold is imposed. A trained score near historical 42% would not show a drop relative to an untuned score of similar size. The fresh matched FP32 baseline is the relevant comparator.

Evaluation interrupted: verify saved responses; infer only missing IDs. Check whether a child process is still alive before launching another GPU job.

Training interrupted at update 19: resume verified checkpoint 16, restoring optimizer, scheduler, RNG and data position. Replay the three unsaved updates. Adapter weights alone are insufficient.

OOM or changed precision/batch: stop, preserve evidence, create a recorded revision. Do not silently mix incompatible settings into one run. Smaller batches reduce memory; 5-shot prompts are longer.
