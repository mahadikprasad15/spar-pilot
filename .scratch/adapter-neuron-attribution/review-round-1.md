# Adapter and neuron attribution — review round 1

Reviewed `fb4f49ff1e28c1259d4b1f455c4caefd89fb8a44`, including the guide, requested context and joint-audit spec, the candidate plan, ticket proposal and all ten tickets. This is a design review, not an implementation or GPU qualification; all proposed values remain unapproved. The points below are for a disposition before implementation or execution.

The stated adapter formula has the right sign for the *local* first-order prediction of `M(g=0) - M(g=1)` when a scalar gate multiplies the active branch at `g=1`. The neuron terms sum to that adapter attribution and are invariant to a nonzero rank-one gauge change, provided they use the same live branch, scale, inputs and token positions. These identities do not by themselves validate full removal or the behavioral proxies.

1. **blocking** — **Protect confirmation and generation observations during rehearsal.** `spec.md` §Selection freeze and §Run tiers; `issues/05a-colab-rehearsal.md` and `issues/05b-pod-qualification.md`: 05a runs ablations and a report on eight production confirmation rows *before* 06 freezes selections; it also generates on ten study-cohort items. Calling those results rehearsal prevents artifact reuse but does not prevent a person from using the observed outcomes to revise the plan or selection. It also conflicts with “before any confirmation row is read.” Use question-disjoint calibration rows and separate generation prompts for all visible tuning/rehearsal, or freeze the complete selection and analysis before inspecting those outcomes and exclude exposed items from confirmation. Distinguish blinded preparation of confirmation traces from inspecting their model/ablation results. Record whether the joint audit's earlier use of this held-out split could have informed the present hypotheses; if independence cannot be established, label the affected result accordingly.

2. **blocking** — **Separate implementation, preparation and authorized GPU execution in the ticket graph.** `ticket-proposal.md` §Graph; `issues/01-trace-inputs.md`, `issues/05a-colab-rehearsal.md`, `issues/05b-pod-qualification.md`, and `issues/06`–`09`: 05a depends on 01, which calls for generating all 300 production traces on a GPU before either GPU rehearsal or qualification. Meanwhile 05a promises an end-to-end 06–09 pipeline, although those tickets are blocked by 05b/06. Make CPU/fixture implementations and the partial exporter available before 05a, and distinguish those dependencies from authorization to run them. Schedule production-trace generation after an expressly approved bounded GPU preparation/qualification step, with separate calibration inputs and budgets for Colab and Pod. The current `needs-triage` text correctly authorizes no spend; the graph should not imply otherwise.

3. **blocking** — **State the actual provenance and conditional population.** `spec.md` §Data and §Questions; `issues/01-trace-inputs.md` and `issues/09-report.md`: “not training questions” overstates the available evidence. The joint-audit sequence record says online-GRPO lineage is partial and establishes only no overlap with *available* sources (`.scratch/joint-neuron-adapter-audit/issues/02-frozen-sequences.md` §2026-11-10). Carry per-arm checked sources and unknowns through the manifest and report; do not call online-GRPO clean. Base-correct filtering also restricts teacher-forced claims to questions solved by the untuned model under this scorer and decoding, not all GSM8K questions or newly acquired ability. Save counts and relevant characteristics for accepted and rejected questions by split, recheck the minimum *after* all mask exclusions, and report the selected-population limitation. Gold-trace robustness can remain deferred if claims stay conditional.

4. **blocking** — **Specify causal-token alignment for `M_acc` and preserve generated IDs.** `spec.md` §Data and §Metrics; `issues/01-trace-inputs.md` and `issues/02-metrics.md`: the joint-audit `response_content` mask identifies token positions, while logits at `t` predict token `t+1`. Masking logits at content positions omits the first content-token likelihood and can include the end-of-turn likelihood; masking *target* content tokens instead scores the intended content including its first token. Choose and state the exact indexed equation, including the header position, EOS and padding, and test it with a hand-computed sequence where each position differs. Save prompt and generated token IDs and stop reasons before decoding; compare any template re-tokenization against those IDs and either use the actual generated continuation or explicitly label a changed tokenization as a different fixed-text estimand.

5. **blocking** — **Define an implementable, nonempty early-stop proxy.** `spec.md` §Metrics; `candidate-plan-v1.yaml` §metrics; `issues/01-trace-inputs.md` and `issues/02-metrics.md`: flexible-v3 accepts correct answers with no `####`, including a single-line response such as “The final answer is 42.” Excluding the final answer line and last five content tokens can therefore leave no positions, and the spec does not define the boundary for prose/boxed answers, boundary-crossing tokens, or the empty-mask policy. Also, the first token obtained by encoding `####` in isolation need not represent that marker in every preceding context; it may be a shared subtoken. Define the prefix contexts/event, verify the actual tokenizer and distinct generation stop IDs, seal offsets and rejection reasons, and report mask coverage without turning an empty mean into zero. Treat mean log token-event probability as a proxy, not an expected length; predeclare how its direction will be checked against actual generation.

6. **blocking** — **Sum attribution over every causally relevant input position.** `spec.md` §Stage A+B; `issues/03-attribution-instrument.md`: the loss masks determine where `M` is read out, but a gate on an earlier prompt or assistant-header token can affect later response logits through attention. The sums in both attribution equations must cover all unpadded branch positions contributing to the metric, not only `response_content` or the M_len mask. State that distinction and test a fixture in which an adapter affects the loss only through an earlier prompt token; compare with an independently applied gate finite difference. Otherwise both attribution paths can agree with each other while omitting the same causal contribution.

7. **blocking** — **Make the PEFT hook and gradient path executable and independently checked.** `spec.md` §Stage A+B; `issues/03-attribution-instrument.md` and `issues/05b-pod-qualification.md`: in the pinned PEFT 0.18.0 `Linear.forward`, `lora_B(lora_A(...)) * scaling` is computed inline; the scaled branch is not itself a child module whose output can simply be hooked. Hooking the wrapped linear's output includes the base output, and constructing a scaled copy only inside a hook does not make that copy part of the forward graph. Specify an actual connected gate/gradient capture, for example on `lora_B`'s output with scale accounted for, and prove its equivalence to a gate on the live scaled branch. Verify active routing and frozen parameters after each `set_adapter`, non-unit scale, independent finite differences, zero/disabled branches, and wrong-branch mutations on CPU and the real qualified model.

8. **blocking** — **Freeze usable and comparable matched controls.** `spec.md` §Selection freeze, §Stage C and §Stage D; `candidate-plan-v1.yaml` §selection and §stage_d; `issues/04-ablation-engine.md` and `issues/08-generation-check.md`: define the eligible population, whether matching is per target or for the group's write distribution and module counts, sampling without replacement, tie/seed rules, and exclusions for the target and selected top sets. A target or another top adapter can otherwise be its own “random” control. The plan creates a matched 10 per metric but Stage D has only one unspecified matched-10 condition for two differently selected top-10 sets. Choose and freeze the comparator for each primary, including what is reported if a match is unavailable; do not silently loosen the tolerance or still assume 60 single-ablation points.

9. **blocking** — **A pooled 60-point correlation does not validate each arm or full removal.** `spec.md` §Statistics and §Controls; `candidate-plan-v1.yaml` §statistics; `issues/07-teacher-forced-ablation.md` and `issues/09-report.md`: pooled Spearman can be driven by between-arm scale differences even when within-arm rankings are wrong; the ten selected singles per arm also share questions and are not 60 independent observations. Rank correlation alone tolerates badly miscalibrated magnitudes. Predeclare per-arm/per-metric agreement, signed magnitude or error diagnostics, ties/near-zero handling and paired question-level uncertainty, along with the pooled summary. Specify how discovery predictions are compared with fixed confirmation effects and how group predictions are formed. Small-step finite differences validate wiring locally, while single and group zeroing measure the actual nonlocal approximation; neither substitutes for the other.

10. **blocking** — **Make failure of the validity gate logically consistent with the primaries.** `spec.md` §Statistics; `issues/09-report.md`: if the gate fails, the spec says primaries 1 and 2 rest on Stage C effects, but Stage C measures only ten selected singles per arm/metric and two groups, not a common 196-adapter causal-effect vector across arms. It cannot recover the stated cross-arm 196-vector correlations, and different arms' selected adapters may not coincide. State which claims become unsupported or exploratory, or predeclare a feasible common ablation set and the narrower comparison it supports. Apply the same distinction to primary 3: the 64-read intervention may be directly measured, but an unvalidated attribution concentration is not established causal sparsity.

11. **blocking** — **Specify the causal contrast and equivalence test for separability.** `spec.md` §Statistics, primary 1; `issues/07-teacher-forced-ablation.md` and `issues/09-report.md`: “M_acc stays within its CI” does not define a comparator or establish that accuracy-related effects are small; a CI that includes zero is not evidence of equivalence. Freeze the paired contrasts for removal of the M_len and M_acc sets versus the appropriate controls, a scientifically meaningful `M_acc` equivalence margin, and a rule requiring the relevant paired interval to fit within that margin. Specify how the Stage D length and accuracy checks, cap/invalid outcomes and uncertainty enter support, contradiction or an inconclusive result. Low attribution correlation and top-set overlap alone establish ranking differences, not distinct behavioral mechanisms.

12. **blocking** — **Freeze the inferential families and the cross-arm ordering test.** `spec.md` §Statistics; `candidate-plan-v1.yaml` §statistics; `issues/09-report.md`: shared question resampling is a sensible starting point, but CI method, the exact Spearman inputs (signed versus absolute vectors and ties), comparisons, missing-arm policy and multiplicity are unspecified. In particular, define whether each GRPO comparison must exceed both Gold comparisons and test paired differences in correlations, not merely non-overlap of separate CIs; define the two k-order contrasts and uncertainty. Predeclare which statements form the primary families and a coherent family-wise rule (for example Holm-adjusted tests or simultaneous intervals), or label unadjusted comparisons exploratory. The selection sets and all bootstrap/family rules must be sealed before confirmation outcomes are inspected.

13. **blocking** — **Separate rescaled-read sufficiency from natural 64-neuron necessity.** `spec.md` §Stage C and primary 3; `issues/04-ablation-engine.md` and `issues/07-teacher-forced-ablation.md`: rescaling a 64-neuron read to the full read's discovery mean absolute value changes the surviving contributions, potentially by a large factor. It tests an engineered rescaled read, so it cannot alone show that the original 64 terms retain 70% of the adapter's natural effect. Include the same frozen subset without rescaling, label the rescaled experiment separately, and report its factor and discovery reference population. Define retained effect explicitly, e.g. `(M_sparse - M_removed)/(M_full - M_removed)` on the same confirmation questions, with a predeclared resolution floor and unavailable handling when the full-removal effect is near zero, changes sign or is nonfinite. Define the ordering of signed neuron attributions and preserve the same rules for term-size and random controls.

14. **non-blocking** — **Make concentration and cancellation well-defined.** `spec.md` §Statistics, primary 3; `issues/09-report.md`: `Σ|attr_j| / |Σ attr_j|` is undefined when the signed sum is zero, and 50%/90% concentration is undefined when total absolute attribution is zero. Freeze numerical-resolution and missing-value rules instead of labeling those cases sparse or dense. A mere permutation of neuron indices leaves a sorted concentration curve unchanged; state whether the “shuffled-index baseline” means accumulation in a random order, a random subset, or another explicit null, with its seeds and interpretation.

15. **blocking** — **Qualify batch-dependent generation and precision before interpreting the comparison.** `spec.md` §Stage D and §GPU utilization; `issues/05b-pod-qualification.md` and `issues/08-generation-check.md`: the largest batch that fits is not automatically behaviorally comparable to pilot batch 1–2, and recording differences on 20 items supplies no rule for material scorer, length or stop-reason changes. Freeze a batch manifest and predeclared diagnostic/stop policy, probe realistic longest prompts through the full 1024-token cap including KV-cache peak, and report item-level changes from the pilot. Use one newly generated full-arm reference and matched batching for the study; reuse the untuned threshold only if the relevant generation protocol, including batching, is compatible. If TF32 is considered, predeclare selection/ranking and effect-stability comparisons and tolerances on disjoint calibration data before inspecting the comparison; do not infer equivalence from 20 raw values alone.

16. **blocking** — **Give the backward sweep a feasible lower range and bounded failure path.** `spec.md` §GPU utilization; `candidate-plan-v1.yaml` §gpu; `issues/05a-colab-rehearsal.md` and `issues/05b-pod-qualification.md`: at 16k padded tokens, 28 materialized FP32 `z` tensors of width 8,960 alone are about 15.3 GiB, before the model, retained graph, gradients, workspaces or logits. Thus even the smallest proposed budget may OOM, especially on a 40 GB Colab GPU; 256k is not evidence of feasibility. Probe smaller budgets, including singleton/longest examples, benchmark the actual two-backward and output-writing path, record failed candidates, and define safe OOM recovery and a stop if no budget meets the policy. Use the qualified production device and measured worst-case memory, not a theoretical utilization target, to choose the frozen budget.

17. **blocking** — **Make partial progress, budget enforcement and restoration specific to this study.** `spec.md` §Outputs and operations and §Run tiers; `issues/06-attribution-run.md`–`08-generation-check.md`: one unit per arm for A+B and per arm/metric for C can discard many completed batches or conditions after interruption and leaves a coarse boundary for a hard cap. Reusing joint-audit Pod/export names does not by itself prove they understand these new results, identities or partial states. Specify sealed resumable batch/condition units with IDs, input/plan/code/runtime hashes, durable status and no duplicate records; expose a parameterized canonical artifact root and save config, logs, per-example structured results and partial manifests. Enforce separately approved qualification/production caps cumulatively at bounded unit boundaries, include export time, and rehearse deletion of local state plus verified restore using the actual attribution pipeline. A Pod-stop policy must be separately authorized and conditional on the appropriate verified backup.

18. **non-blocking** — **Make the rehearsal exercise each new intervention, not merely a count of conditions.** `issues/05a-colab-rehearsal.md` §What to build and `issues/05b-pod-qualification.md` §What to build: “three Stage C conditions” and “two generation runs” could omit the 64-read path, constant read, or an edited-checkpoint generation path. Name a small covering set that exercises no-op, single/group removal, subset read and constant read, plus full versus an edited generation checkpoint; use independent fixture or calibration data. Verify online upload/readback of this study's partial outputs and the child-process logs, and include a corruption/interruption test. This keeps the rehearsal small while making its claimed end-to-end coverage auditable.

19. **non-blocking** — **Qualify utilization and MFU as estimates.** `spec.md` §GPU utilization; `issues/05a-colab-rehearsal.md` and `issues/05b-pod-qualification.md`: `6N` FLOPs/token approximates training with weight gradients; here the base weights are frozen and backward is primarily for activation/input gradients, so it need not be the correct numerator. Attention work also varies with sequence length and padding. State the FLOP model and its exclusions, the actual device/precision peak denominator, synchronized timing and warm-up, and enough sample duration for a 1 Hz NVML summary. CPU tiers have no NVML data. Treat the 85% busy and 50% memory figures as performance-investigation targets, not scientific validity gates or reasons to inflate batches after a safe measured configuration is found.

20. **question** — **What role does the fixed-read claim play?** `spec.md` §Arms and sources and §Stage A+B; `issues/09-report.md`: the neuron decomposition and rank-one gauge invariance hold for the *current* `a` even if it changed during training. Is `a ≈ a₀` intended only as a separate historical interpretation? If so, define its checkpoint alignment/gauge convention, threshold, initialization provenance and near-zero handling, and avoid making a valid within-checkpoint attribution conditional on that comparison. Raw factor closeness is gauge dependent.

21. **question** — **What exactly is the constant-read condition?** `spec.md` §Stage C and §Deferred; `issues/04-ablation-engine.md` and `issues/05a-colab-rehearsal.md`: define `c̄` (signed or absolute, equal-example versus token weighting, discovery positions including prompt/header, and the frozen arm/module) and its gauge-consistent application at every relevant position. Is a cached autoregressive constant-read generation path intended now? Stage D defers neuron-condition generation, so if it is not needed, keep it out of this pass; if it is needed, add a real cached-generation test and freeze the condition before evaluation.

22. **blocking** — **Do not equate likelihood of one base trace with accuracy.** `spec.md` §Problem statement, §Metrics and §Stage D; `issues/08-generation-check.md` and `issues/09-report.md`: an adapter can lower the likelihood of the untuned model's particular correct wording while producing a different correct solution, or raise that likelihood without improving generated accuracy. The teacher-forced and generation cohorts also differ, and only two of six arms receive generation checks. Name the first quantity trace likelihood throughout, define the planned comparison between its frozen condition-level changes and paired generation accuracy/length changes, and report disagreements and uncertainty. Limit direct behavioral claims to the arms and conditions actually generated; a two-arm check does not establish the proxy for the other four. This does not require adding the deferred gold-trace experiment.
