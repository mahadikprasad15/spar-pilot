# Overnight chain and code-reuse review

Reviewed `5a50513`, focusing on the overnight additions, ticket 11, the reuse handoff and the actual referenced code. The overall design can stay small: these are integration fixes and targeted tests, not a request for new experiments. CPU implementation can continue; resolve and test the relevant items before an unattended launch. No GPU qualification or run has been performed in this review.

1. **blocking — Avoid returning every full-width LoRA branch gradient.** `spec.md` §Stage A+B; `issues/03-attribution-instrument.md`; `handoff.md` §Reuse map. The spec asks `torch.autograd.grad` for every captured `lora_B` output, so it retains and returns full-width gradient tensors for all adapted modules simultaneously. At 16,384 padded tokens, the gate/up outputs alone are `2 × 28 × 16,384 × 8,960 × 4` bytes = **30.6 GiB** of returned FP32 gradients, before the other modules, retained outputs, base graph and model. Recomputing z and chunking the head do not remove this allocation. For rank 1, compute each adapter attribution from the scalar read already needed for neurons: `−Σ_t c_t · ∂M/∂c_t`; the gradient through the actual branch already includes its scale. Capture only those scalar reads/gradients for all modules, or use an equally bounded method. Compare it with the independent branch-output oracle, including non-unit scale and both metrics. A tiny Qwen2/PEFT CPU check over all seven projections gave maximum per-example absolute difference `4.5e-8` at scale 2. Still benchmark actual peak memory: other retained activations remain.

2. **blocking — Seal and restore this study's actual outputs.** `issues/05-units-export.md`; `issues/11-overnight-chain-runner.md`; `handoff.md` §Reuse map. `neuron_audit_export.snapshot()` recognizes `BlockStore` units and particular sealed-run layouts; arbitrary `run_summary.md`, `run_summary.json`, selections or response JSONL are treated as unsealed and omitted by default. A local fixture containing only the two proposed summary files produced a **partial snapshot with no included files**. Seal the launch record, frozen selections, trace/results JSONL, summaries and related metadata in an export-supported layout, or extend the snapshot contract. Declare expected files/units and test a fresh restore of both a complete run and a failed partial run, including the morning summary and missing-work list. Do not equate a successful upload/readback of an incomplete scope with a complete study.

3. **blocking — Make the watchdog and teardown honor both the stop policy and artifact integrity.** `spec.md` §Overnight unattended chain; `issues/11-overnight-chain-runner.md`. The watchdog currently copies “whatever” is local while the scientific writer may still be updating it, and neither the copy nor the stop command has a bounded execution time. At the deadline, stop/join the writer and background writers, preserve only sealed, hash-verified units, and put timeouts around copy, export and each stop attempt. Persist elapsed budget across restarts so the watchdog uses the *remaining* cap rather than starting a fresh full timer. The requested policy is to stop even after HF export failure; the old `neuron_audit_export.may_stop_pod` instead requires a verified HF restore, so it cannot be reused unchanged for that decision. Explicitly record an unverified/failed volume copy and possible missing outputs if neither backup can be verified, while still following the user's approved stop policy; never label that copy verified. An in-Pod watchdog cannot guarantee stop after its container, credentials or host fail: record stop *requested* versus externally verified and exercise failed/hung copy and stop paths in tests. Finalize and persist the summary/receipt after the copy and export outcomes are known, before requesting stop.

4. **blocking — Preserve the intended metrics when adapting the old numeric code.** `handoff.md` §Reuse map; `issues/01-trace-preparation.md`, `issues/02-metrics.md` and `issues/08-stage-c.md`. `token_measurement_math.prediction_positions()` expects full-length boolean masks named `question`, `solution`, and `user`; passing a response-content-position fixture raises `KeyError('question')`. Adapt/parameterize its target-shift logic for this study's masks rather than using it unchanged. Separately, `stage0_drift_backend.DriftEngine` compares **variant ‖ untuned** and projects its KL head in FP64, whereas this study specifies **full arm ‖ ablated condition** and FP32 forwards. Use the old engine as a pattern, with an explicitly constructed same-arm unablated reference, correct KL direction and declared precision. Test masks with distinct prompt/content positions and a three-distribution fixture where `KL(full ‖ cut)`, its reverse and `KL(cut ‖ untuned)` differ. Likewise, `stage0_push_backend.collect` is a pattern, not a drop-in collector: it requires zero B and enables adapter-weight gradients.

5. **blocking — Reconcile crash resume with the existing single-writer marker.** `issues/11-overnight-chain-runner.md`; `handoff.md` §Reuse map. Ticket 11 promises relaunch after interruption, but the reused `neuron_audit_production.Marker` refuses a different live or stale marker unless `resume_own=True`; that override also bypasses the ownership check, so setting it blindly can permit two writers. Define the actual recovery rule: verify this run's previous worker is gone and its volume/identity and sealed units match before resuming; for ambiguous or foreign writers, stop safely for investigation rather than automatically taking over. Add separate tests for a killed worker's stale marker, a genuinely live writer and an ambiguous marker. Do not describe the marker as a distributed lock.

6. **non-blocking — Avoid a premature overrun stop from length-sorted work.** `spec.md` §Overnight unattended chain; `handoff.md` §Reuse map. The existing `overrun_check` extrapolates `elapsed / fraction_of_units`, while `neuron_audit_qualify.pack` sorts longest examples first. Two early projections can exceed a cap even if the remaining shorter work would finish inside it; this study also has unlike attribution, ablation, generation and export stages, and the plan does not establish a qualification projection for each. For the smallest reliable first pass, enforce the approved hard caps at unit boundaries and treat forecasts as advisory, or explicitly qualify stage-specific, length-aware projections before using them to stop. Include a longest-first fixture so a healthy run is not cut short merely by its packing order.

7. **non-blocking — Clarify the launch record and small rehearsal.** `handoff.md` §Rules; `spec.md` §§Run tiers and Overnight unattended chain; `issues/11-overnight-chain-runner.md`. The handoff says null tolerances stay null until 06b, while 06b is unattended and the launch record must contain fixed values or fixed rules before it starts. Keep the candidate plan proposed, but require the approved record to resolve required tolerances and caps before launch; a derived resolution floor can be an approved rule evaluated in 06b. The two-arm rehearsal must validate against its explicitly labeled two-arm expected set, while production still refuses missing arms. Test an unavailable matched group as a recorded skipped condition so it does not accidentally abort the chain.
