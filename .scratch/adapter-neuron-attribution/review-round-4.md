# Implementation review — critical findings

Reviewed `claude/bold-gauss-5qkzwi` at `7be1df9b2124a50922c8978f1198aa0c1e83cf36`, against the attribution spec and tickets. Scope is defects that can prevent the run, lose or misidentify work, bypass a gate, or materially misstate the result. No GPU or paid-resource run was performed. These are review-time findings, not claims that an experiment has already run or that results are invalid.

1. **blocking — CUDA finite differences cannot run.** `pilot_eval/attribution_stages.py` (`finite_difference_check`, around lines 586–608) creates batched gates with `torch.full` on the CPU; `attribution_instrument.branch_gates` and `neuron_gate` multiply them by model outputs on CUDA. The shapes are non-scalar, so PyTorch raises a device mismatch. Moving the gates alone is insufficient: the metric helper also calls `.numpy()` directly on CUDA tensors. Both the 06a covering set and 06b qualification call this function. Create gates on `ids.device` and move metric values to CPU before conversion. Exercise this path on a real GPU or with a device-sensitive regression test; CPU-only tests do not reveal it. A local PyTorch meta-device check reproduced both device-mismatch and `.numpy()` failures, but is not a GPU benchmark.

2. **blocking — a failed qualification is bypassed on resume.** `attribution_chain.Chain.run` stores qualification in `state['completed']` before `_signoff` and saves it even when sign-off fails (around lines 414–445). On the next start the completed stage is skipped, without checking that a valid sign-off exists. A CPU harness reproduced a failing check followed by a resumed run that reached production with `signoff=None`. Persist completion only after successful sign-off and require a matching, verified sign-off before any production work on every start.

3. **blocking — loaded sources are not bound to their sealed identities.** `attribution_backend.TransformersBackend` accepts independently supplied `adapter_dirs`, `model_dir` and test parquet (around lines 54–69). `sources()` verifies the inventory and sequence records, but does not compare those independent inputs with them; `check_live_adapter` only compares the loaded model against the very directory supplied. Swapping two valid arm directories or using another compatible base/test file can therefore produce valid-looking results under the wrong arm or cohort label. Verify each actual adapter's payload/config against that arm's sealed step-64 inventory entry, and bind the actual base model and test data to their pinned hashes before work. This is a code-inspected risk, not evidence that any supplied paths were wrong.

4. **blocking — resume trusts a sealed unit without checking its identity.** `attribution_chain.run_units` and `run_conditions` skip any hash-intact key before constructing or comparing the expected identity (around lines 278–309). A fixture reused a unit after its plan, code, runtime and example IDs were changed. A valid hash only proves the old bytes are intact; it does not prove they belong to this run. Compare the stored identity with the expected one before skipping, and refuse mismatches.

5. **blocking — recovery from lost local disk and interrupted Stage D is incomplete.** The chain reads completed-stage state from the volume but never restores its sealed files to the local root before skipping those stages (`attribution_chain.Chain._start` / `run`; `attribution_stages`). In a CPU fixture, deleting local work after copying a sealed qualification to the volume caused the next attempt to skip qualification and fail reading its absent local file. Separately, a Stage D edit creates `attribution/edited/<arm>/<condition>` before generation, but `edit_checkpoint` uses `mkdir(exist_ok=False)`; a retry after interruption raises `FileExistsError`. Stage D also retains all generated batches in memory and seals only a whole condition, so an interruption loses that condition's progress. Restore and verify required artifacts first; make edited checkpoints reusable or safely reconstructible; seal and resume Stage D per batch as specified. Edited checkpoints currently appear as unsealed files in the export scope and can also make snapshots partial.

6. **blocking — elapsed caps are not enforced cumulatively.** `Budget.start` resets the clock mark; `Chain.run` does not charge elapsed time at ordinary stage completion, and teardown does not charge export time (`attribution_units.Budget`, `attribution_chain.Chain.run` / `teardown`). A CPU harness with a simulated 200-second preflight and 50-second preflight cap completed with zero budget elapsed. Stage D checks boundaries only after an entire condition, not each batch. Charge and persist all stage and export time, enforce caps at completion and real unit boundaries, and test a restart. The independent watchdog provides a separate last-resort deadline but does not make the per-stage accounting correct.

7. **blocking — a previous watchdog can stop a resumed writer.** `scripts/attribution_overnight.sh` starts an independent watchdog but does not cancel or transfer ownership of an old one when a killed worker is resumed. The old watchdog later signals its original PID and invokes the Pod stop even if a replacement writer is active. This was reproduced locally with a mock stop command and a live replacement process; no Pod was touched. Bind watchdog ownership to an attempt and safely retire or disarm prior watchdogs before resuming; verify the writer is the same attempt before signalling or stopping.

8. **blocking — the final summary is missing from the HF backup, and retries can copy a stale one.** `Chain.teardown` uploads before `au.write_summary` (around lines 485–505), even though the summary is in the expected export scope. A fake-Hub execution produced a partial snapshot without the morning summary, and `restore_summary` failed. On a subsequent attempt, a different summary is written to an alternate nested path while `_summary_to_volume` still copies the old canonical summary; a fixture ended with a successful retry and a volume summary saying `failed`. Seal the final summary before the final verified snapshot, and make the canonical/attempt-specific summary and its backup outcomes consistent. Test clean-root restore of both successful and failed attempts through the actual chain teardown.

9. **blocking — qualification can approve memory demands it never tested.** `_generation_batches` (`attribution_stages.py`, around lines 242–266) tests at most 20 rehearsal items but can select a batch size of 32 or 64; the real Stage D then uses that many distinct items. The token-budget sweep similarly labels a candidate by its nominal token budget even when the finite calibration set cannot fill that budget; production packs more rows at that budget. The generation sweep also does not handle a candidate OOM as a failed candidate. Record actual batch size/padded tokens and measured peak; do not qualify an unexercised production size, and make OOM fall back according to the approved rule. A real-GPU qualification remains necessary.

10. **blocking — report can overstate evidence near the resolution floor or after multiple-testing correction.** `attribution_report.primary3` checks whether the full-removal denominator interval excludes zero, but the approved resolution floor is computed only after `build` and is not applied to R (`attribution_stages.report`; spec §Tolerances). A CPU fixture with a denominator of 1e-12 and a floor of 1e-3 returned R=0.9 and `sparse`; it should be unavailable under the spec's floor rule. Separately, `primary1` labels the interval-based result `supported` before Holm is applied, with the adjusted result only later in the report. A fixture produced raw p=0.0056 and Holm-adjusted p=0.0952 while the headline still said supported. Preserve the requested raw interval result, but explicitly distinguish it from the family-adjusted inference; do not present an unadjusted outcome as adjusted support.

11. **blocking — the 06a rehearsal computes logits on a blinded generation-cohort item.** The rehearsal's edited-generation check calls `TransformersBackend.stage_d_generator`, which unconditionally probes `self.cohort_items()[0]` for gate/checkpoint equivalence (`attribution_backend.py`, around lines 170–180). This path remains after `7be1df9` changed the rehearsal stage's generated items. The spec prohibits model outputs on the ADR 0001 cohort before the discovery freeze. Pass an explicitly allowed rehearsal prompt into the check, and assert that no cohort model forward occurs in rehearsal. Only equality is surfaced by this check; no actual rehearsal or resulting information exposure was established in this review.
