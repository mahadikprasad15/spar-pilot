## Section 1: proposed policy

- **Identity checks:** Adopt as proposed the bit-for-bit live/saved comparison and 1e-6 layer-max z reconstruction, plus the 1e-5 sum-of-absolute-terms tolerance for the read and branch. Explicitly handle zero reference scales as exact-zero or unresolved; never silently divide by zero. These values are not validated by CPU tests or approved for a GPU run yet. The review did not supply an explicit disabled-base/logit pass bound or a definitive batch-agreement gate, so those fields remain open rather than claiming qualification is fully specified.
- **FP64 resolution:** Propose a calibration-only, per-arm/per-layer 99th-percentile error for paired D values from approximately ten examples, same underlying FP32 parameter values cast to FP64, same input/masks and comparable eager backend. Keep per-neuron errors and max as well; report a <5× floor flag. This is not a guarantee for the discovery set, and the 99th percentile can hide large errors in the top 1%. A zero observed error does not prove infinite resolution: label it unresolved rather than replacing it with FP32 spacing and calling that a measured bound. Keep batch-composition comparisons as separate robustness evidence; same batches do not guarantee that model-dependent rounding cancels.
- **Statistics:** Propose the requested 50th-percentile activity floor, pooled sample SD, 1e-6 low-spread rule, fine 0/50/75/90/95/99/100 bins, 2,000 question/conversation bootstraps with seed 1234, 1,000 null draws indexed by seeds 10000–10999, and seed-43 100/100 math split halves. Specify deterministic derived streams by comparison/layer/direction and aligned pooled draws. Tied quantile boundaries, the background split-half rule, and exact zero-floor behavior need explicit review.
- **Benchmark and runtime:** Propose FP32/TF32-off eager production and a matched benchmark, 80% VRAM ceiling for probed configurations, and all-head collection at <=1.5× overhead and <=60% of verified usable volume capacity. Layers 10–17 are a candidate fallback only if those layers exist and a subset check fits the absolute storage/time budget; otherwise omit 1B. FUSE's nominal free-space figure alone cannot justify the 60% calculation. The 2× production-overrun rule needs a defined observation window and forecast; stop only at a safe boundary and save a verified partial export. The user will choose hard hours after seeing benchmark results. Incomplete arms can be labeled partial, never complete.
