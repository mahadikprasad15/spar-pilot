# Joint neuron and adapter audit — Phase 1, review draft v2

**Status:** needs-triage. The implementation choices below are the proposed review baseline, not an approved production run. The separate review response records where the external review was accepted or qualified.

## Problem statement

We need an inspectable comparison of native neuron activations and adapter reads for the untuned model and six trained runs, on identical fixed texts. Existing Stage 0 artifacts provide checkpoints, model inputs and some collector infrastructure, but the existing collectors do not by themselves perform this neuron audit. The result is descriptive; it cannot establish what causes model behavior.

## Solution and scope

Phase 1A collects per-example statistics from every MLP `down_proj` input, independently builds candidate lists, and compares discovery lists with matched controls and held-out observations. Conditional Phase 1B measures `o_proj` input slices by attention head if a real-GPU benchmark supports it. Independently verifiable evidence and resumable, partial exports are required throughout. Generation, accuracy evaluations, gradients, cuts, ablations, steering and retraining are outside this phase.

## User stories

1. As a researcher, I want the same token IDs, masks, batch membership and padding across arms so activation differences have an interpretable paired input.
2. As a researcher, I want available training, rollout and selection provenance checked so possible leakage and unknowns are visible.
3. As a researcher, I want the saved and live adapter tensors and routing checked so a silently inactive adapter cannot produce a misleading comparison.
4. As a researcher, I want native activation, signed read and physical adapter writes kept distinct so factor sign and scale do not become false effects.
5. As a researcher, I want independent discovery lists, activity-matched nulls, stability and fixed-list held-out results so I can judge robustness.
6. As an operator, I want a live progress display, durable work units, safe resume and recoverable partial exports so a failure does not waste the whole run.
7. As a reviewer, I want source gaps, numerical resolution, statistical limits and explicit arm coverage in the report so partial results cannot masquerade as complete comparisons.

## Implementation decisions

### Sources, data and batches

- Intended arms: untuned baseline; step-64 Gold SFT, online GRPO, offline GRPO and Sampling SFT k0/k2/k5. The local imported offline-GRPO run includes step-0 and step-64 `adapter_model.safetensors` and trainer-state files, and a step-64 internals report used by the existing heatmap. Local tensor hashes match that report's recorded checkpoint hashes. The saved training plan records rank 1, alpha 1, dropout 0, 28 layers and seven projection types, and its original checkpoint-zero config is present and matches the recorded original-config hash. **But** the step-64 config recorded by the internals report has a different hash from that original config and is absent from the local checkpoint directory. Trace the internals loader and recover the actual step-64 config/seal/lineage; do not substitute the original config merely because its high-level parameters match. These are not yet an independently verified complete source chain.
- Missing/unsupported arms are explicit, not zeros or a complete seven-arm result. If an adapter's scale or targets are unresolved, do not claim its adapted-model activation or list B ranking has been measured: the incoming z itself depends on a correctly loaded adapter. A raw factor ranking on separately obtained base inputs, if produced at all, is a labeled shared-input diagnostic, not the arm's actual list B.
- Use parameterized stages: source inventory, data preparation, CPU instrument, real-GPU qualification and benchmark, production collection, selection, report, and partial/final export. Reuse existing source and checkpoint verification, Stage 0 pre-hook and export machinery where their contracts apply. Existing source code assumes 28 layers, rank 1, alpha 1 and specific targets; audit dimensions and mappings must come from verified model/checkpoint metadata, not be silently generalized.
- Inventory hashes, file sizes and identities of model, tokenizer, template, actual adapter payloads, configs, active PEFT key lists, initialization, source datasets and available training/rollout/selection lineage. Preserve file hashes and parameter hashes as different identified algorithms. Resolve model/adapter configuration, versions, dtype, hardware, attention backend, target modules and LoRA scale in a sealed run manifest.
- Select 200 discovery and 100 held-out GSM8K train questions where the union of available training, rollout and selection IDs and normalized question hashes shows no overlap. Prepare a separate calibration split targeting 25 additional math and 25 general-background examples from the same independently screened pools, disjoint by question/conversation from discovery and held-out. State which source sets were checked and what is missing; incomplete provenance is **unknown cleanliness**, not a clean result. If the preferred pool is insufficient, record and review a new fallback, preserving a disjoint final evaluation set.
- Pin background dataset revision and license. Extract first-turn prompt/response pairs only, test multi-turn records, apply the documented non-math/non-code filter and save a human-reviewed sample. General and number-containing near-miss background groups are disjoint at the conversation level, with actual counts; target 200/100 and 70/30 respectively. Split each source by question or conversation, seed 42. A filter does not remove the math/background source, style, length or authorship confound.
- Format pairs once with the actual chat template and freeze full token IDs, sample IDs, truncation records and masks. For an ordinary Qwen2.5 assistant response, the observed template renders `<|im_start|>assistant\n{content}<|im_end|>\n`: `response_content` excludes padding, prompts, header/template tokens, EOS/end-of-turn and trailing newline; `reply_start` is the last token of the assistant header before content, expected to contain the header newline; `termination` includes the `<|im_end|>` token and the preceding token. Do not assume the header newline is always a standalone token: use actual token offsets and reject boundary-crossing ambiguity. Save human-readable token/mask decodes for three representative examples, including empty/truncated boundaries and special-token displays. An activation at position t is after processing token t. Reject ambiguous or empty primary masks instead of silently assuming boundaries.
- Data preparation freezes token sequences and length metadata. GPU qualification chooses a feasible token budget and **then** freezes an ordered batch manifest of example IDs, padding lengths and position IDs. Production uses identical batch membership, order, padding and masks in every arm; hash and verify the manifest at the worker. This avoids a circular dependency between a GPU benchmark and earlier token preparation. Identical shape reduces one source of discrepancy but does not prove numerical errors cancel.

### Precision, instrument and adapter activation

- Production forwards and saved per-example summaries are FP32; TF32 is disabled for CUDA matmul and cuDNN, autocast is off, model is in eval/inference mode, and the actual attention backend, deterministic settings and flags are recorded. Eager attention is proposed for both production and the FP64 comparison, pending benchmark review; do not compare FP64 eager against a different FP32 backend and label the difference purely dtype error. The numerical issue motivates FP32 but does not prove every smaller bf16 effect is lost. FP16 storage is not used for statistics that will be subtracted or ranked. BF16 is a small, separately labeled qualification comparison, not production or a substitute for FP32.
- Register a pre-hook on the actual PEFT-wrapped `mlp.down_proj`. Capture z after gate activation times up projection, including active gate/up adapter effects. For each example, position group, layer and neuron, FP32-accumulate and store mean z, mean |z| and counts; derive equal-example-weighted means as primary and token-weighted means separately. Base adapter fields are null. Read actual saved a, b and scale s; for rank one, c_t = aᵀz_t, signed term = a_j z_j, adapter write = s b c_t, and write magnitude = |s| ||b|| |c_t|. Save c_t by token with example and position mapping, and retain signed and magnitude summaries.
- Validate against **independent** instrument paths: reconstruct z from the captured MLP input and the actual active gate/up branches and activation; independently capture the active PEFT `lora_A` output and compare it with aᵀz; capture the actual adapter-branch output and compare to s b c_t, with dropout disabled. Do not compare two values computed from the same hooked tensor as the sole validation. Include synthetic wrong-layer, shifted-mask and wrong-sign mutations that each make the appropriate test fail. Hook both `o_proj` head reconstruction and per-head read identity if 1B is enabled.
- For every arm and expected target, compare the live active-adapter A/B tensors to the verified saved values, keys, shapes and dtype, bit-for-bit when loading preserves dtype; reject unexplained missing/unexpected keys, dtype casts, merge/disable state or routing. Compare `disable_adapter()` with a separately loaded same-base reference, and verify the active branch changes the direct output and, on representative examples, model logits. A verified genuinely zero update, zero input/read, or sub-resolution logits is not proof of a broken load: classify it, use additional designed probe inputs and independent tensor/routing evidence, and stop or explicitly mark the arm/module unresolved if activity cannot be established. A zero b at step 64 defaults to **unresolved** until provenance/training evidence explains it; do not silently equate it with a correctly active trained module.
- The sign and magnitude of a, b, c_t and individual signed read terms have rank-one gauge ambiguity: (a,b) → (k a,b/k), including k < 0, leaves the same ΔW. Signed terms are meaningful within a fixed checkpoint's convention, but raw signs/magnitudes are not directly comparable across arms. Prefer physical vector writes s b c_t. An optional signed cross-arm scalar comparison must document a reference, alignment rule and near-orthogonal/near-zero exclusions; b-direction alignment is a convention, not proof of comparable functions. Within-arm rankings by |a_j z_j| are unchanged by a common nonzero factor rescaling. Compare a with its actual initialization, including cosine, relative norm and common-input read change only where verified initialization exists; even cosine depends on the saved gauge convention.

### Numeric qualification, batch benchmark and resolution

- The real-GPU qualification stage runs after the CPU instrument and the partial-export capability, before the production plan is frozen. It tests every arm's live checkpoint and routing, same-input hashes, module/layer dimensions and reference loader, then benchmarks 20–50 calibration examples with 1A hooks alone and 1A+1B hooks, base and one adapter. Benchmark FP32, TF32-off, actual production backend and same hooks. Record throughput, batch and adapter-load timing, peak GPU memory and projected output bytes. Select a feasible token budget and 1B scope from these measurements using a reviewed cost criterion; <=32k padded tokens is only an initial upper bound to probe, not a safety guarantee. The user chose to set a hard wall-time cap **after** the benchmark but before production.
- Candidate 1B policy: all layers only if 1A+1B time is at most 1.5× 1A and projected output stays within 60% of *trustworthy usable* volume capacity; otherwise consider layers 10–17 only after measuring/checking that subset against the same absolute storage and runtime budget, otherwise omit. Do not use a nominal FUSE free-space figure as proof of usable quota. Choose the largest actually probed token budget with peak VRAM <=80% of device capacity, subject to a separate realistic long-input stress probe and stable output behavior. These are proposed bounds, not already-approved or guaranteed-safe thresholds.
- Measure FP32 numerical sensitivity using repeated identical base/arm batches, alternate batch compositions/padding and singleton comparisons as a separate robustness diagnostic. On about ten representative disjoint calibration examples, compare paired base-vs-arm D values in FP32 with a reference computed using the same FP32 parameter values cast to FP64, same masks/batch and comparable eager attention. For each arm/layer compute the 99th percentile across neurons of |D_FP32 − D_FP64|; report per-neuron error, median and maximum as well. This is a calibration-sample-dependent reference, not a universal error bound; flag selected entries below 5× that layer's measured value as exploratory. If the floor is zero, mark the ratio unresolved rather than inventing a minimum spacing as a proven error bound. FP64 OOM/unsupported means qualification is incomplete pending a reviewed fallback; do not assume every A100 has the same memory or that another backend is equivalent.
- The proposed identity tolerances, activity-bin and statistical parameters and benchmark rules are in the explicitly **unapproved** candidate plan. They use sum of absolute rank-one terms for read/branch checks to avoid a near-zero denominator when terms cancel. They need review before being frozen, along with a disabled-base/logits criterion, batch diagnostic policy, FP64 fallback and cost limits. Do not import the existing Stage 0 generation 1e-3 threshold or widen any agreed rule after failure. Matching batches reduces shape variation but does not prove numerical drift cancels between models.

### Candidate lists, nulls and estimates

- From discovery only, per layer build independent A, A-nb, B and D lists. A and A-nb first retain the top 10% by base math mean |z|, then rank the standardized math-minus-general or math-minus-near-miss activity difference. B ranks each arm's mean |a_j z_j| on math. Let d_ij be adapted minus base per-example mean |z_j| for neuron j. The primary D score is **|mean_i d_ij|**, not mean_i |d_ij|; retain its signed mean and the separate mean-z change. Secondary D-relative is |mean_i d_ij| / mean_i base mean |z_j| where the frozen activity floor is met. N, native write size, is optional.
- The candidate plan proposes base-activity quantile boundaries 0/50/75/90/95/99/100 per layer; the layer's 50th-percentile activity as a floor for ratios/relative D; pooled sample SD `sqrt(((n1-1)*s1^2+(n2-1)*s2^2)/(n1+n2-2))`; and a low-spread flag below 1e-6 times layer-median activity. These are **proposals**, including tie/zero-floor handling that must be resolved before freezing. If the layer median or actual denominator is zero, do not allow a zero denominator merely because it meets the percentile floor: flag the relevant statistic unresolved. Freeze deterministic ties by neuron index, eligible populations, per-layer top-64 primary budget, top-32 sensitivity, floors and exclusions before inspecting discovery results. Derive bin boundaries from base-discovery activity only and seal before overlaps. Do not pad intersections, divide by near-zero activity/spread, or label an undefined value zero. Five or more seeded layer/activity-matched control groups per list are descriptive controls; distinguish them from the larger overlap null below.
- For each layer and comparison X vs Y, freeze bins using base discovery math activity and state the exact eligible universe. Keep observed X fixed and sample Y-sized sets **without replacement within each bin**, matching Y's actual bin counts, from the same eligible layer universe (including X where eligible); draw at least 1,000 independently seeded sets. For A vs another list, the null candidates need not all meet A's top-decile gate: the tested null is exchangeability of Y conditional on base-activity bin, not a claim that the list-selection rules are identical. For D-vs-D, select and declare which arm's D is fixed and which is randomized; record asymmetric direction. Where a valid matching draw is impossible, report unavailable rather than switch nulls. Report observed overlap, null median and 2.5/97.5 percentiles, with seeds and simulation count. These are randomization reference intervals conditional on bins, not confidence intervals or proof of significance, and matching activity does not control every confound.
- Proposed primary descriptive family: step-64, `response_content`, discovery math versus disjoint general background, top 64, and four comparisons A/B, A/D, D across arms and B/D within arm. Report every relevant arm or arm pair with each layer and the **equal-layer average of the per-layer overlap fraction**, using the actual selected list sizes and explicitly excluding/flagging undefined layers; give a matched-null distribution for that pooled statistic using aligned per-draw layer simulations. Secondary/exploratory: A-nb, D-relative, top 32, other position groups, other metrics and head analyses. All comparisons remain exploratory with one training seed; label the number of comparisons and do not select an apparently significant result after the fact.
- Freeze full-discovery lists and controls before examining held-out results; the collector may store held-out data earlier but selection and human review must not use them. On held-out data compute A's math-minus-background selectivity; B's math read-term magnitudes and background values; D's mean paired change and directional agreement with its signed discovery effect, marking zero/undefined signs. Compare each fixed list with its frozen matched controls; do not re-rank on held-out. Report per-example paired bootstrap intervals and split-half discovery stability, using a predeclared resampling count, method and seed. Report raw values, activity binning and B∩D for both D rankings.

### Storage, recovery and export

- Do not use one parquet row per neuron/example. Write immutable dense FP32 array blocks by arm, position group, layer, statistic and stable example-row range; each has shape `[block_examples, intermediate_size]` with a sealed index mapping IDs and masks/counts to rows. The layout must support partial blocks and resume without rewriting a sealed full layer. Store compact per-token c_t and offset/index arrays separately; derive magnitude from c_t, s and ||b||. Storage estimates are data-dependent: for E examples, L layers, J neurons, A arms, G groups and two FP32 stats, payload is `A*G*L*E*J*2*4` bytes before indices, controls and temporary/export copies. For illustration only, E=700, L=28, J=8960, A=7 and G=3 produce about 27.5 GiB of dense payload; actual dimensions, counts and groups must be measured. If there are 165,000 counted tokens per arm and 28 layers, c_t alone would add about 17.6 MiB per adapted arm, excluding indexes and other outputs. Use actual counts to budget both network-volume and local temporary capacity; stream reductions immediately and do not cache full token-by-layer activations.
- Source bytes are fully hashed at inventory, output blocks once when sealed. On resume verify every reused output block against its recorded hash and size. A size/mtime alone is not a content integrity guarantee: use immutable content-addressed source identities only if the storage contract genuinely guarantees them; otherwise rehash each needed source once per resumed process/session, never once per layer/arm/work unit. Failed integrity is distinct from an interrupted attempt, and must remain visible.
- Use one Pod, one tmux session and one scientific writer process per run. A local advisory marker records run ID, host, PID and heartbeat; the operator/runbook enforces exclusivity. It is not a distributed lock and cannot prevent concurrent writers on another host. Check for an existing marker/process before launch, preserve failure evidence, and treat stale or ambiguous state as requiring manual investigation, never automatic takeover. If future use requires multi-host writers, design a separate reliable coordination mechanism first.
- Preflight runs in the actual launcher and each scientific worker checks its own effective interpreter, prefix, pinned packages, cache paths, offline setting and runtime before expensive work. Set offline flags before importing Hub libraries; perform a real offline model/tokenizer cache load in the worker. Record `sys.executable`, `sys.prefix`, `HF_HOME` and the Hub's resolved cache without exposing credentials; do not rely solely on resolving a venv Python symlink, which can point at system Python. If workers are subprocesses, validate there too. For HF network authentication/write/readback, use an explicitly online client/process with the same intended credentials, separate from the offline model loader, and record sanitized outcomes.
- Preflight checks actual network-volume attachment; write, read, rename, fsync and cleanup in both output and local temporary locations; source inventory, cache and GPU; pinned imports; private repo and actual write/readback; configured RunPod command version **only if** stop automation uses it; remaining space, time and cost. A FUSE free-space figure is not necessarily a real quota guarantee. Time and label expensive checks, reuse verified identities safely, and report concrete remediation without printing secrets.
- Run via a persistent remote session; use unbuffered, line-oriented logs, a durable timestamped progress record per sealed work unit and status showing completed/total, stage, arm, PID/host and age of last progress. A stale record is a warning requiring investigation, not proof of failure. Never equate an SSH disconnect with job failure. Timeouts preserve failure evidence.
- Default export mechanism: configured private Hugging Face **dataset** repo `Prasadmahadik/spar-sampling-sft-artifacts` using the existing Hub API/manifest upload and a fresh pinned-revision download to an independent temporary directory; allow an explicit configured alternative. Preflight must verify privacy and actual write/readback, not just `whoami`. Export can be invoked after preparation, any successful stage or failure, without waiting for a report. Snapshot only sealed, stable files plus sanitized failure/status, config, manifest, indexes and budget/timing; label it partial or complete and list missing/unsealed items and omitted reconstructible inputs with exact recovery requirements. Verify the independent downloaded files and hashes, save the revision/receipt, and test restoration into a clean root. A verified partial export is not a complete audit. Automatic Pod stop, if configured, is allowed only after a verified appropriate export and the frozen policy; export failure leaves the Pod running and reports potential billing. Include upload, readback and failure handling in wall-time/cost accounting. After benchmarking, the user selects a hard wall-time cap before production. A proposed 2× benchmark-projection overrun triggers graceful checkpoint/export only after an agreed observation window and forecast method are specified; do not stop based on a noisy first batch.

## Testing decisions

- CPU: a tiny random Qwen/PEFT model, no model downloads, exercises independent hook identities and negative controls, saved/live weights and active routing, gauge transformations, first-turn tokenization and masks, variable batches, paired reductions, dense-block indexing, exact discovery eligibility, frozen held-out behavior, activity-stratified null and underfilled controls. Test external behavior at existing prepare/run/status/verify seams where practical.
- Keep CPU failure fixtures focused on observed issues: wrong interpreter, missing cache/files, enabled-but-missing hf_transfer, HF authentication, FUSE storage-permission failures, excessive repeated verification, non-updating progress and incompatible RunPod CLI only if automatic stopping is used; also cover killed-run resume, a corrupt sealed unit and upload/readback/restore. Mock cloud I/O. The advisory marker is not a cross-host lock. No mock result is GPU qualification.
- Real GPU: all-arm loading/routing and active-effect qualification, representative FP32/bf16/FP64 and batching diagnostics, measured hook benchmark and a small end-to-end block before production. Save the identity of the exact GPU, software, model, batches and reviewed numeric policy. Passing a small sample is evidence within its coverage, not a guarantee for all neurons or later runtimes.
