# Experiment engineering lessons

Read this before designing or building experiment, evaluation, or remote-run workflows. During review or investigation, add or update a lesson when a serious finding could affect future work. Keep entries concise and link to evidence; distinguish a demonstrated failure from a code-inspected risk and update the status only after verification. Track specific fixes in the project issue tracker and add focused regression tests where useful. Record lasting design decisions in an ADR when the rationale needs to survive implementation changes.

## Neuron audit review, 2026-11-11

Review of commit `ed4e8d3`; findings below are review-time observations, not assertions about current fix status. Check the current code and tickets before acting on them. The 152 audit tests passed on CPU in the project environment; no real-GPU qualification or full production run was established by that review.

- **Test the real export path.** An online preflight can pass while the production worker remains offline and cannot upload. Run a small upload and fresh readback through the same online process used by the real exporter. The offline Hub failure was reproduced. Evidence: `pilot_eval/neuron_audit_production.py` (`main`, `_package_arm`) and `pilot_eval/neuron_audit_preflight.py` (`hf_online_subprocess`).
- **Exercise recovery with an empty local disk.** A resume test that keeps the original Pod's local files does not establish recovery on a new Pod. Verify all expected batches are restored or packaged from persistent storage, and that a complete export contains every expected unit. A missing restore request was reproduced; incomplete export was identified by code inspection. Evidence: `pilot_eval/neuron_audit_production.py` (`_collect_arm`, `_package_arm`) and `pilot_eval/neuron_audit_export.py` (`package_arm`, `publish_final_manifest`).
- **Verify the persistent mount, not just a writable path.** A writable directory can be on ephemeral Pod storage. Check the actual mount and intended volume identity before calling a copy durable. This was a code-inspected risk. Evidence: `pilot_eval/neuron_audit_preflight.py` (`storage_probe`, `volume_record`).
- **Bind measurements and resumed work to their actual inputs and runtime.** Verify the loaded adapter, sequences and code against the qualified records; bind reused qualification and blocks to compatible runtimes and run identities. Reject conflicting duplicate arm/example records. Silent replacement of a duplicate with a different plan identity was reproduced with a fixture; other identity gaps were code-inspected. Evidence: `pilot_eval/neuron_audit_production.py` (`check_qualification`, `_load_state`, `_collect_arm`), `pilot_eval/neuron_audit_qualify.py` (`Qualification`), and `pilot_eval/neuron_audit_selection.py` (`Discovery`).
- **Treat malformed lineage as unresolved.** A present file is not evidence that it was successfully parsed; fail or explicitly mark coverage incomplete if question text cannot be read. A malformed JSONL line causing question hashes to be discarded was reproduced. Evidence: `pilot_eval/neuron_audit_sequences.py` (`_lineage_file`, `_leakage`).
- **Enforce elapsed-time limits independently of forecasts.** Check the actual approved budget at work-unit boundaries, account for previous attempts and export time, and report whether the Pod remains billable. Missing qualification enforcement and production checks only at arm boundaries were identified by code inspection. Evidence: `pilot_eval/neuron_audit_qualify.py` (`Qualification.run`) and `pilot_eval/neuron_audit_production.py` (`Production.run`).
- **Test version checks against the target GPU build.** An exact comparison of `2.9.0` and `2.9.0+cu128` rejected the latter in a reproduction. Define and record the intended package and CUDA-build policy before deployment. Evidence: `pilot_eval/neuron_audit_preflight.py` (`check_interpreter`).
- **Keep reporting caveats and controls visible.** Label proxy numerical floors as proxies, retain per-layer references and show matched controls. A signed average across neurons can hide large opposite-direction changes; report an appropriate magnitude alongside it. These were identified by code inspection and a small numerical example. Evidence: `pilot_eval/neuron_audit_report.py` (`build`, `render`).
