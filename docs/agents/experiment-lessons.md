# Experiment engineering lessons

Read this before designing or building experiment, evaluation, or remote-run workflows. During review or investigation, add or update a lesson when a serious finding could affect future work. Keep entries concise and link to evidence; distinguish a demonstrated failure from a code-inspected risk and update the status only after verification. Track specific fixes in the project issue tracker and add focused regression tests where useful. Record lasting design decisions in an ADR when the rationale needs to survive implementation changes.

## Neuron audit review, 2026-11-11

Review of commit `ed4e8d3`; findings below are review-time observations, not assertions about current fix status. Check the current code and tickets before acting on them. The 152 audit tests passed on CPU in the project environment; no real-GPU qualification or full production run was established by that review.

- **Test the real export path.** An online preflight can pass while the production worker remains offline and cannot upload. Run a small upload and fresh readback through the same online process used by the real exporter. The offline Hub failure was reproduced. Evidence: `pilot_eval/neuron_audit_production.py` (`main`, `_package_arm`) and `pilot_eval/neuron_audit_preflight.py` (`hf_online_subprocess`).
- **Exercise recovery with an empty local disk.** A resume test that keeps the original Pod's local files does not establish recovery on a new Pod. Verify all expected batches are restored or packaged from persistent storage, and that a complete export contains every expected unit. A missing restore request was reproduced; incomplete export was identified by code inspection. Evidence: `pilot_eval/neuron_audit_production.py` (`_collect_arm`, `_package_arm`) and `pilot_eval/neuron_audit_export.py` (`package_arm`, `publish_final_manifest`).
- **Verify the persistent mount, not just a writable path.** A writable directory can be on ephemeral Pod storage. Check the actual mount and intended volume identity before calling a copy durable. This was a code-inspected risk. Evidence: `pilot_eval/neuron_audit_preflight.py` (`storage_probe`, `volume_record`).
- **Bind measurements and resumed work to their actual inputs and runtime.** Verify the loaded adapter, sequences and code against the qualified records; bind reused qualification and blocks to compatible runtimes and run identities. Reject conflicting duplicate arm/example records. Silent replacement of a duplicate with a different plan identity was reproduced with a fixture; other identity gaps were code-inspected. Evidence: `pilot_eval/neuron_audit_production.py` (`check_qualification`, `_load_state`, `_collect_arm`), `pilot_eval/neuron_audit_qualify.py` (`Qualification`), and `pilot_eval/neuron_audit_selection.py` (`Discovery`).
- **Treat malformed lineage as unresolved.** A present file is not evidence that it was successfully parsed; fail or explicitly mark coverage incomplete if question text cannot be read. A malformed JSONL line causing question hashes to be discarded was reproduced. Evidence: `pilot_eval/neuron_audit_sequences.py` (`_lineage_file`, `_leakage`).
- **Enforce elapsed-time limits independently of forecasts.** Check the actual approved budget at work-unit boundaries, account for previous attempts and export time, and report whether the Pod remains billable. Missing qualification enforcement and production checks only at arm boundaries were identified by code inspection. Evidence: `pilot_eval/neuron_audit_qualify.py` (`Qualification.run`) and `pilot_eval/neuron_audit_production.py` (`Production.run`).
- **Test version checks against the target GPU build.** An exact comparison of `2.9.0` and `2.9.0+cu128` rejected the latter in a reproduction. Define and record the intended package and CUDA-build policy before deployment. Evidence: `pilot_eval/neuron_audit_preflight.py` (`check_interpreter`).
- **Keep reporting caveats and controls visible.** Label proxy numerical floors as proxies, retain per-layer references and show matched controls. A signed average across neurons can hide large opposite-direction changes; report an appropriate magnitude alongside it. These were identified by code inspection and a small numerical example. Evidence: `pilot_eval/neuron_audit_report.py` (`build`, `render`).

## Neuron audit Colab rehearsal r1, 2026-11-11

Bounded rehearsal on Colab (A100-SXM4-40GB, Python 3.13, torch 2.9.0+cu128) of 03b → 04 → 05; each failure below was demonstrated on that run and fixed with a regression test. Ticket notes: 03b, 04, 05 under `.scratch/joint-neuron-adapter-audit/issues/`.

- **Make child-process errors visible.** Colab does not display a subprocess's own stderr, so a failed step showed only an exit code. Stream the child's stdout and stderr into the notebook. Fixed in `61797dc` (notebook `sh()`).
- **Remove preinstalled packages that pin to another build.** After pinning torch 2.9.0, Colab's preinstalled torchvision no longer matched, and `transformers` imports torchvision whenever it is present, so `import peft` failed (`operator torchvision::nms does not exist`). Uninstall packages the experiment does not use before pinning. Fixed in `735ff59`.
- **Do not let test fixtures supply what the real model lacks.** Qwen2.5's `config.json` has no `pad_token_id` (the pad token is in `tokenizer_config.json`); the CPU fixture set one, so every real arm failed only on GPU. Take such values explicitly from the pinned source used in training, record them and recheck them downstream. Fixed in `c5d4f1a` (`pilot_eval/neuron_audit_collector.py`, `neuron_audit_qualify.py`, `neuron_audit_production.py`).
- **Bind resumable stages to the code that produced them.** A sealed preflight stage from an earlier commit was reused after a fix, so the summary named the wrong commit. Production stage identity now includes the code commit and every stage records it. Fixed in `2d53bb3` (`pilot_eval/neuron_audit_qualify.py`).
- **Make rehearsal subsets cover every group the later stages need.** Longest-first packing puts short GSM8K rows only in the last batches, so a first-batch rehearsal gave selection zero math rows and an opaque numpy error. Choose covering subsets and refuse clearly on empty groups. Fixed in `558e77e` (`pilot_eval/neuron_audit_production.py`, `neuron_audit_selection.py`, `neuron_audit_report.py`).
- **Apply rehearsal reading modes in every stage that reads the subset.** 05 read only rows every arm collected, but 06's held-out reader did not, so the report asked for all 97 held-out math rows (and its error wrongly said "discovery"). The report now uses the same rehearsal mode and names the split. Fixed in `cf376d8` (`pilot_eval/neuron_audit_report.py`, `neuron_audit_selection.py`).
- **Capture every child process a notebook step starts, including the last one.** The evidence upload succeeded but its receipt line went to the child's own output, which Colab hides; the receipt had to be read from the saved file. Fixed in `e8e9e46` (notebook evidence cell). Evidence for the whole rehearsal: `neuron-audit/rehearsal-evidence-r1/` at revision `17ad7108` in the private HF dataset.

## Neuron audit Pod rehearsal pod1, 2026-11-12

Small rehearsal on a Runpod A100-SXM4-80GB (Python 3.12.3, torch 2.9.0+cu128, CUDA 12.8, cuDNN 91002) with Global Volume sl-0 at `/workspace` (FUSE, separate device), code `cc80cb7`. 03b sealed every stage (logits agreement 3.6e-4 to 5.7e-4; FP64 floor on GPU for all six arms); 04 was interrupted after 3 units, the local working directory was deleted, and the resumed run logged `units-restored-from-volume` for gold-sft, skipped the already verified untuned package, and finished all seven arms (2 units each). A clean-root `restore-final` from HF was complete for every arm and restored the qualification package; `safe_to_stop_pod` was true. Outputs are labelled `rehearsal-pod-pod1` (final manifest `neuron-audit/rehearsal-pod-pod1/final/63429805….json`, HF revision `6e623fcd`).

- **Check the container disk size before installing anything.** Runpod's default 50 GB container disk (43 GB free) is below what the full run's local working set needs under the 60% storage rule, so the real 03b would have refused only after setup and model download. The Pod had to be recreated with a 120 GB disk. `facts` now reports `disk_problems` when less than 60 GB is free (`pilot_eval/neuron_audit_pod.py`). Fixed in the commit that adds this entry.
- **A Pod stopped for balance loses only the container disk.** The volume identity file on sl-0 survived a full Pod replacement, so `init-volume` is a once-per-volume step; the venv, clone, prep and model are rebuilt in about 10 minutes.

## Neuron audit production run v1, 2026-11-12

Approved plan `frozen_plan_v1.approved.yaml` (code `c466535`), unattended `neuron_audit_pod chain` on a Runpod A100-SXM4-80GB with sl-0. 03b qualified in about 33 min with no review flags (batched-vs-singleton logits 4.1e-4 to 6.2e-4, bound 1e-3); the rule-labelled sign-off was recorded and 04 ran in about 55 min: all seven arms, 9 units each, 54.98 GB of verified packages, final manifest `complete` (`neuron-audit/pod-v1/final/21bb5c72….json`, HF revision `3ac96cdc`; record in `.scratch/joint-neuron-adapter-audit/final-record-v1.json`). Evidence copies: `/workspace/neuron-audit/evidence-v1/` on sl-0.

- **Exercise the Pod-stop command for real before relying on it.** 04 reached a verified final backup but `runpodctl pod stop <id>` exited 1: the Pod image's runpodctl accepts `runpodctl stop pod <id>` (newer releases document `pod stop`). No rehearsal stops the Pod, so this was never run; the event recorded only a return code. The Pod stayed up until stopped by hand. The stop command now tries `stop pod` then `pod stop`, and its output is logged with the event (`pilot_eval/neuron_audit_pod.py` `stop_command`, `neuron_audit_production.py`). Fixed in the commit that adds this entry.

## Attribution design review, 2026-11-13

- **Keep confirmation outcomes out of visible rehearsals before selection is frozen.** A rehearsal label prevents reuse of its artifacts but cannot prevent people from adapting a later plan after seeing outcomes on the same questions. Use separate calibration questions or freeze the selection and analysis first. This is a design-time risk, not a claim that leakage occurred: the draft schedules a confirmation-subset ablation report before the selection freeze. Evidence: `.scratch/adapter-neuron-attribution/spec.md` (§Selection freeze and §Run tiers), `issues/05a-colab-rehearsal.md` in that folder, and `.scratch/adapter-neuron-attribution/review-round-1.md` (point 1).
- **Size retained activations from the formula before choosing a backward design.** The draft held `down_proj` inputs for all 28 layers during backward and estimated ~4 GB; at 16k padded tokens it is 16,384 × 8,960 × 4 B × 28 ≈ 15.3 GiB before the model, graph and logits. Draft v2 stores only the per-token scalar ∂M/∂c_t and recomputes z in a forward-only pass. Design-time finding from review point 16, not an observed OOM. Evidence: `.scratch/adapter-neuron-attribution/review-round-1.md` (16) and `review-response.md`.
- **In PEFT 0.18.0 the scaled LoRA branch is not a module output.** `Linear.forward` computes `lora_B(lora_A(dropout(x))) * scaling` inline, so a hook on the wrapped linear sees base + branch, and a scaled copy built inside a hook is not in the graph. Gate the `lora_B` output instead; the scale cancels in ⟨∂M/∂out, out⟩. Code-inspected (review point 7); to be confirmed by the CPU fixture in ticket 03.
- **Give a frozen model a differentiable input when measuring activation gradients.** In a tiny Qwen2/PEFT 0.18 CPU reproduction, freezing every parameter and multiplying each branch by the constant `1.0` left logits without a gradient graph; backward failed. Marking the embedding output as requiring gradients made backward succeed while weights stayed frozen. This is a design-time risk in a possible implementation, not a failure of existing attribution code. Evidence: `.scratch/adapter-neuron-attribution/review-round-2.md` (point 23).
- **Budget the gradients returned by autograd as well as saved activations.** The proposed rank-one attribution requested every full-width branch gradient simultaneously; gate/up gradients alone would occupy about 30.6 GiB at 16k tokens. A tiny Qwen2/PEFT CPU check found the scalar-read contraction agrees with the branch-output contraction, so it can avoid that returned-gradient allocation. This is a design-time estimate, not a measured GPU peak. Evidence: `.scratch/adapter-neuron-attribution/review-round-3.md` (point 1).
- **Test the actual export scope with new file types.** In a local fixture, `neuron_audit_export.snapshot` marked standalone `run_summary.md` and `run_summary.json` unsealed and included neither. Put new outputs in a supported sealed layout or extend the export contract, then verify they appear in a clean-root restore. Evidence: `.scratch/adapter-neuron-attribution/review-round-3.md` (point 2).

## Attribution implementation (CPU), 2026-11-13

- **Leaving `disable_adapter()` unfreezes the adapter in PEFT 0.18.0.** After `with model.disable_adapter(): ...` exits, the active adapter's `lora_A`/`lora_B` weights have `requires_grad=True`, even if they were frozen before. Reproduced on the tiny Qwen2 fixture. A frozen-weight instrument that computes an untuned reference this way silently gets trainable adapters on its next pass. `attribution_instrument.frozen_disable_adapter` restores each parameter's flag, and the instrument refuses any unfrozen weight. `set_adapter` likewise marks the new adapter trainable, so re-freeze after every switch.
- **FP32 finite differences have a resolution floor.** For a metric of size |M| at ε = 1e-2, central differences resolve only about ulp(|M|)/ε ≈ 1e-5. Effects near that size cannot validate an attribution. Compare against effects well above it, and state the floor alongside any finite-difference tolerance (06b's real-model check uses ε = 1e-2 in FP32).

## Attribution implementation review, 2026-11-14

- **Gate resumption on the decision, not just a completed calculation.** A CPU fixture reproduced a failed qualification being marked complete and skipped on restart, allowing production without sign-off. Persist successful sign-off atomically with completion and require it again on resume. Evidence: `.scratch/adapter-neuron-attribution/review-round-4.md` (2); review-time observation; fixed in `3cf8537` and verified by a CPU test (`review-response-round-4.md`, 2).
- **Exercise actual teardown and recovery, including the final summary.** A fake-Hub chain exported before writing its summary, so a clean restore lacked it; a retry with local work deleted also failed despite a sealed volume copy. Test the actual ordering and restoration, not only isolated serialization helpers. Evidence: `.scratch/adapter-neuron-attribution/review-round-4.md` (5, 8); review-time observations; fixed in `3cf8537` and `f5dc3bb`, verified by CPU chain tests (`review-response-round-4.md`, 5 and 8).
- **Test device boundaries in the real GPU validation path.** A CPU fixture can pass while non-scalar CPU gates are multiplied by CUDA outputs and CUDA tensors are converted directly to NumPy. Inspect device placement and test the real GPU path before qualification. Evidence: `.scratch/adapter-neuron-attribution/review-round-4.md` (1); code-inspected GPU failure, with a local meta-device reproduction but no GPU run. Fixed in `50d6245` with a CPU test that fails on both patterns; the GPU path itself is not yet verified (06a).

## Attribution fixes review, 2026-11-14

- **Reconstruct expected work as well as saved work on resume.** A local chain/Hub fixture resumed from completed-stage state after a failed volume copy and marked a backup complete even though the restored freeze was absent. Persist expectations and compare them against verified artifacts before skipping stages or declaring completeness. Evidence: `.scratch/adapter-neuron-attribution/review-round-5.md` (2); fix deferred by agreement until before an unattended launch (`issues/11-overnight-chain-runner.md`).
- **A rejected launch must not disarm a live watchdog.** The real launcher changed its owner token before validating its record; a local mock demonstrated that a failed second launch could supersede the original watchdog while its writer kept running. Evidence: `.scratch/adapter-neuron-attribution/review-round-5.md` (3); no real Pod was involved; fix deferred by agreement until before an unattended launch (`issues/11-overnight-chain-runner.md`).
